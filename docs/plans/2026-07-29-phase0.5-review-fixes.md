### Task D3: Coalesce stream deltas at 250ms

**Files:**
- Modify: `internal/agent/engine.go` (the stream handler in `events()`)
- Test: `internal/agent/engine_stream_test.go`

**Finding (C1), half two, and C2's trigger:** the handler emits one frame per SDK event, each carrying the **entire accumulated message**, so wire volume is O(response²). The branch's own test shows 2 text deltas producing 5 `message_update` frames. A 16 KB reply at realistic 15–50 char chunks is 330–1100 frames averaging ~8 KB — **2.6–8.8 MB for one LLM call**, and `agentloop` allows 20 iterations per turn. That frame *count* is what fills the 256-slot per-subscriber bus buffer in Task D4's failure chain.

**Do not "fix" this by switching to pi's `text_delta` event.** Its schema is `{type, contentIndex, delta, partial: AssistantMessage}` — it carries the full partial too, so the frame size is unchanged. Coalescing is the lever.

**Interval: 250ms**, chosen deliberately — this is a reading surface, not a game. That is ~4 frames/second, cutting a 10-second reply from ~1000 frames to ~40 and per-call bytes from ~8.8 MB to ~320 KB.

- [ ] **Step 1: Write the failing test**

```go
const streamFlushInterval = 250 * time.Millisecond
```

In `events()`, alongside `acc` and `streamed`, keep a `lastFlush time.Time`. In the handler, after the `hasContent` gate:

```go

		// Coalesce: one frame per streamFlushInterval, not one per SDK event.
		// Each frame carries the whole accumulated message, so emitting per
		// event makes wire volume O(response^2) — thousands of multi-KB frames
		// per turn, which saturates the per-subscriber bus buffer and evicts
		// the ring. 250ms is ~4 frames/second: imperceptible for reading, and
		// a ~25x reduction. The handler is synchronous on the send goroutine,
		// so this needs no lock.
		now := time.Now()
		if !lastFlush.IsZero() && now.Sub(lastFlush) < streamFlushInterval {
			return

		msg := e.em.mapMessage(&acc)
		e.em.StreamStart(msg)
		e.em.StreamDelta(msg)
```

`StreamEnd` already emits the final message from `OnTurn`, so the tail is delivered regardless of where the last flush landed. **Do not add an end-of-stream flush in the handler** — it would double-emit.

- Modify: `internal/server/server.go:140-144`
- Test: `internal/server/server_test.go`

**Finding (C2):** `Deliver` does a synchronous `protocol.WriteFrame(c.conn, frame)` with **no deadline**, and its own comment admits *"Errors here are silently discarded"* — a `_ =` on a fallible write, against this project's explicit rule. It is called from `monitorChild`'s single goroutine. Chain: a subscriber stops reading (`fundi tail` into a pager, a suspended terminal, a laggy attach) → socket buffer fills → `WriteFrame` blocks forever → `monitorChild` blocks → the child's 256-slot bus buffer fills → `Bus.Publish` **silently drops**.

Dropped frames include `message_end`, `agent_end`, `agent_settled`, and `tool_execution_end`. `attach/src/session.ts:973` waits for `agent_settled` (or a non-retrying `agent_end`) to declare idle — lose it and the TUI hangs "streaming" forever. And `monitorChild` also drives status transitions, rename detection, session-id sync and `handleChildExit`, so blocking it stalls all bookkeeping for that child.

Pre-streaming a turn was ~10 bus frames and 256 was unreachable. Task D3 cuts volume ~25×, but a genuinely stuck subscriber still blocks indefinitely — this is the actual fix, and it is worth having on its own merits.
