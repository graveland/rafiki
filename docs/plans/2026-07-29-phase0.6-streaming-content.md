# Phase 0.6 — Streaming Delivers No Content

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make streamed `message_update` frames actually carry the partial assistant message, and add the assertion whose absence let a completely non-streaming implementation pass twelve tests, nine independent reviews, and a whole-branch review.

**Architecture:** One root-cause fix in `MapAssistantMessage`, plus the missing content assertions. No protocol change, no rafiki change.

**Tech Stack:** Go 1.26, `anthropic-sdk-go v1.37.0`.

## The bug, measured

Run against the real Anthropic API on 2026-07-29 (evidence: `.superpowers/sdd/2026-07-29-phase0.5-review-fixes/live-measurement-frames.jsonl`), a three-paragraph reply produced:

```
message_start   out=    3 blocks=0 textlen=0
message_update  out=    3 blocks=0 textlen=0     × 23
message_end     out=  839 blocks=1 textlen=2696
```

All 23 `message_update` frames are **empty**, frozen at the `message_start` snapshot. The whole reply lands in `message_end`. Coalescing and frame timing work correctly; the frames carry nothing. **Functionally this is still batch delivery** — an attached TUI does `_streamingMessage = ev.message` per update (`attach/src/session.ts:606-611`), gets an empty message, renders nothing, then `message_end` dumps 2696 characters at once.

## Root cause

`internal/agent/emit.go`'s `MapAssistantMessage` dispatches on `b.AsAny().(type)`. In the SDK:

```go
func (u ContentBlockUnion) AsText() (v TextBlock) {
	apijson.UnmarshalRoot(json.RawMessage(u.JSON.raw), &v)   // reads RAW JSON
	return
}
```

`anthropic.Message.Accumulate` creates each block **once**, from `content_block_start`'s raw JSON — where `text` is `""` — then grows it by mutating the struct field (`cb.Text += delta.Text`, `messageutil.go:42-44`). It never rewrites `u.JSON.raw`.

So on an accumulating message, `b.Text` grows while `b.JSON.raw` stays empty forever:

- `hasContent` (`engine.go`) reads `b.Text` **directly** → sees growth → flushes. Correct.
- `MapAssistantMessage` goes `AsAny()` → `AsText()` → unmarshals **stale** raw JSON → empty text → dropped by its own `if v.Text != ""` guard. Wrong.

The two functions disagree about the same object, and only the flush gate is right.

`message_end` maps correctly because it is built from rafiki's returned complete `*anthropic.Message`, where the SDK parsed a real response and `JSON.raw` **is** populated.

**This is not limited to text.** `AsToolUse()`, `AsThinking()`, and every other `As*()` read `u.JSON.raw` identically, so `tool_use` and `thinking` blocks vanish from `message_update` the same way.

## Why every test passed

`TestEngine_StreamsDeltasAndPricesFinalMessageOnce` asserts frame *types* in order, then asserts content on the final **`message_end`**. Of the seven streaming tests, three touch text — and every one of them asserts on `message_end`, never on a `message_update`.

**No test asserts that an intermediate frame carries partial content.** That single missing assertion is the entire gap: it is the only thing distinguishing working streaming from batch delivery with extra frames.

### Task F2: Assert that a `message_update` carries partial content

**Files:**
- Test: `internal/agent/engine_stream_test.go`

**Interfaces:**
- Consumes: F1's fix.
- Produces: no production code.

This is the assertion whose absence let the bug through every gate. Seven streaming tests exist; three touch text; **all three assert on `message_end`**. Nothing has ever checked an intermediate frame's content, which is the only thing that distinguishes streaming from batch delivery with extra frames.

- [ ] **Step 1: Write the test**

```go
// The gap that let a completely non-streaming implementation pass twelve
// tests, nine independent reviews, and a whole-branch review: every prior
// content assertion targets message_end, which is built from the complete API
// response and therefore maps fine even when every intermediate frame is
// empty. THIS is the assertion that distinguishes streaming from batching.
func TestEngine_MessageUpdateCarriesPartialText(t *testing.T) {
	// Script several deltas whose accumulated prefixes are distinguishable.
	eng, fe := newStreamingTestEngine(t /* deltas "Hel","lo"," world" */)
	if err := eng.Prompt(ctx, "hi"); err != nil {
		t.Fatal(err)
	}

	texts := assistantUpdateTexts(t, fe) // text of each assistant message_update, in order
	if len(texts) == 0 {
		t.Fatal("no assistant message_update frames")
	}
	for i, s := range texts {
		if s == "" {
			t.Fatalf("message_update[%d] carried no text; frames are flowing but empty — this is batch delivery with extra frames (texts=%q)", i, texts)
		}
	}
	if last := texts[len(texts)-1]; !strings.HasSuffix("Hello world", last) {
		t.Errorf("last update text = %q, not a prefix of the final message", last)
	}
}
```

Adapt to the real fixtures. Note coalescing (250ms) means you may get **one** update for a fast scripted turn — that is correct and sufficient: the assertion is that updates are non-empty, not that there are many. Do not add sleeps to force more.
