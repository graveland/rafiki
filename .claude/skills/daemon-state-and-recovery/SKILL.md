# Daemon state, capture, and recovery

This is "what's durably true after a restart, and how does the DB prove it" —
the inbox's at-least-once vs. consume-once split, conversation leases and
daemon ownership, the message tree every write goes through, and how Claude
Code's own threads/subagents get reconstructed into rafiki's conversation model.
The tree's model, hashing, backfill and cutover procedure live in
`docs/reference/conversation-tree.md`; this file carries the operational rules
that bite when you touch it. Same discipline as CLAUDE.md: rule + where it's
enforced, no incident narration, prune when stale.

- **`conversations.raw_http_request` stores bodies in JSONB, but LLM traffic is frequently not JSON.** `nilJSON` (`pkg/rawtrace/rawtrace.go`) wraps any non-JSON payload (SSE bodies, HTML error pages) as a JSON string before insert, or Postgres rejects the row. `RawTraceStore.Insert` is best-effort (logs and returns nil on failure), so a regression here is silent. When querying `resp_body`, expect either a JSON object or a JSON string holding raw text.
- **One credential scheme: `base64url(sha256(token))` in an indexed TEXT column, for both `users` and `executors`.** Not bcrypt — tokens are 256 bits of `crypto/rand`, so a work factor defends nothing, and bcrypt can't be indexed (every auth would be a full-table scan). `users.HashToken` and `executorsdb.hashToken` must stay identical; the `executors.credential_hash` column comment claiming "bcrypt/argon2 digest" has always been wrong.
- **`users` rows are TOMBSTONED, never deleted, and joins must be by id.** `username` is unique only among ACTIVE users (partial index `users_username_active`), so a query joining by name can return multiple rows — `pkg/insights/search.go`'s owner filter carries `ORDER BY created_at DESC LIMIT 1` for exactly this.
- **An auth failure and an auth OUTAGE are different answers on both surfaces.** `users.ErrNotFound` → 401/`ERR_AUTH_INVALID`; any other store error → 503/`ERR_INTERNAL`, never 401 — a 401 tells clients to discard their credential, so answering a DB blip with 401 logs out everyone at once. Never forward the store's error text to the peer (a pgx error carries the DSN). Same rule as `executors.IsTerminalAuthError` (executor-plane skill).
- **The first admin is minted on the daemon host, and only there.** Connect's `CreateUser` never mints an admin and requires an admin credential, so with zero users the TLS listener authenticates nothing — the daemon logs ONCE at startup: `no users exist: create one on this host with rafikid user create <name> --admin --token`, which opens `RAFIKI_DB` directly (no running daemon, no token; `--admin` is never inferred). `RAFIKI_CONTROL_LISTEN` without `RAFIKI_DB` is fatal at startup.
- **A hypertable with columnstore rejects `ADD COLUMN ... REFERENCES`, but accepts the same FK as a separate `ADD CONSTRAINT`.** `0019_user_attribution` does this for `conversation_turn.author_user_id`. Never "solve" this by dropping columnstore or leaving the column app-enforced.
- **`conversations.v_analysis` and `v_finding` do NOT depend on `v_conversation`** — they read `conversation_analysis`/`analysis_finding` directly (confirmed via `pg_depend`), so `DROP VIEW v_conversation CASCADE` reaches only `v_turn`. Two design docs in this repo claim otherwise; trust `pg_get_viewdef` over them. The view-body chain is 0007, 0008, 0011, 0019 — review all four before touching `v_turn`. `owner_canonical`/`owner_kind` no longer exist as of 0019 (superseded by a direct `users` join).
- **A skill row is unique within a LAYER, and there is no partial `WHERE enabled` index any more.** `skills_layer_key` is `(namespace, name, owner_user_id, (source = 'rafiki-core'))` with `NULLS NOT DISTINCT`, so core, global (owner NULL) and user each get one row per name — which is what lets a user override a core skill without disabling it. Every skill-set write goes through `PutSet` (`pkg/skillsdb`) under the `skillsWriteLockKey` advisory lock; it never changes an existing row's `enabled` flag and refuses a namespace another source holds in the same layer (`NamespaceHeldError`). `SetEnabled`/`Delete` act on a resolved row id, never on a name alone. Probe a scratch database before assuming an upsert design's error semantics.
- **A kill is not complete when `ch.Shutdown` returns — wait for `cm.Remove`.** Status only becomes `exited` when `handleChildExit` calls `MarkExited`, asynchronously on `monitorChild`'s goroutine. Any path reporting a kill as done, or touching on-disk state afterwards, must call `waitForChildRemoval` first. `Kill`, `Forget`, and `ShutdownAllChildren` all do this.
- **Connect response payload shapes are not uniform — read the proto (`proto/rafiki/v1/control.proto`) and the `pkg/connectapi` handler before writing a client-side decode, never infer from a sibling RPC.** `ConversationStats` returns the domain value as an opaque JSON string; `ConversationSearch` wraps its rows in a `rows` field; protojson renders `int64` as a string. Build response fixtures from the generated descriptor, and confirm against a live daemon.
- **Response payloads are size-capped, not streamed-unbounded.** A handler returning unbounded-size data must clamp or size-check the payload — `protocol.ErrPayloadTooLarge` (mapped to `CodeInvalidArgument` by `connectapi`'s errCodeTable) over `ConversationExport` and the recall/tree byte budgets are the established patterns.
- **The event buffer only schedules now; persisted inbox rows are the batch, not `eventbuf.Delivery`.** `Push`/`PushNow`/`PushSteer` persist a row with the right `inbox.Mode` and decide *when* to ask for delivery — coalescing happens at flush over pending rows, not in-memory buffer state. Stickiness (a group holding any `ModeSteer` row delivers as a steer) is a property of the data now, so it survives a daemon restart. `Buffer.fire` must still run its flush callback with `b.mu` released — flush reaches `Controller.deliverInbox` → `sendFrame`, a blocking write, and pushing from inside that path would deadlock on re-entrant acquire. A batch that comes due while its fundi parent is mid-turn is steered, not deferred, when `Controller.steersWhenBusy` says so (subagent settles and job exits only; heartbeats, schedules and notifications still wait for `DrainIdle`): `Buffer.SetSteerWhenBusy` swaps in `flushInboxSourceSteer`, and `Queue.DeliverSteer` upgrades the grouped batch at delivery, since the row was accepted as a prompt before the child's state was known. Without it a coordinator that chains tool calls never ends the turn the batch was deferred to (`TestEligibleBatchSteersWhenBusyAfterDebounce`, `TestSteersWhenBusyIsFundiCompletionNewsDuringATurn`).
- **Two of `inbox.Store`'s five mutating methods — `MarkSent` and `MarkConsumed` — take NO `childID`; the per-child scoping elsewhere is caller discipline, not interface-enforced.** `pkg/inboxdb`'s implementations run `UPDATE ... WHERE id = ANY($1)` against nothing but the row ids. What keeps them from crossing children in practice is entirely in `pkg/inbox/queue.go`'s `Queue`: `Consume`/`deliver` take the per-child lock and only ever pass ids sourced from that same child's own `Pending()`/`Coalesce()` output. A caller combining ids from two children finds no guard stopping it.
- **A fundi child is IN-PROCESS, which is why an inbox row is acked on DEQUEUE rather than on `sendFrame` returning — but a smaller crash window stays open right after the ack.** `Engine.worker`'s own comment names the residual gap between the ack and `agentloop.Run`'s `AppendUser` (a mutex-held stdout write plus a DB rollup with a 3s timeout) as seconds, not microseconds — a crash there loses an acked prompt with no durable trace. A `claude` child has no ack signal at all (`awaitAck` forced false for non-fundi kinds), so its queue doesn't survive a restart.
- **An acked prompt can be deterministically un-persisted, and that is intentional.** `agentloop.Run` calls `conv.RetractTailUser` when the first LLM call on a fresh message fails `llm.IsPromptTooLarge`; on the tree that is a HEAD MOVE (`store.RetractHead`), not a delete — the prompt row survives as an abandoned leaf and the smaller retry becomes its sibling. Since `Engine.worker` acks the inbox row BEFORE running the turn (a crash mid-turn must not replay a prompt already worked on), an oversized prompt ends up acked AND off the working path, leaving only an `agent_error` frame. Don't "fix" this by leaving such a row unacked — the prompt is deterministically oversized, so an unacked row is a poison pill that replays and fails forever. One loud failure beats an infinite loop.
- **`SpawnRequest.MaxDepth/MaxCost/MaxChildren` are pointers because zero is meaningful for all three — they collapse to plain values in `childstore.Session`, where `MaxCost == 0` means UNLIMITED, not "spend nothing".** Every comparison against a stored budget must be guarded by `if snap.MaxCost > 0` first, or every unbudgeted agent refuses its first spawn. The collapse happens in `grantedCost`/`grantedDepth`/`grantedChildren` (`cmd/rafikid/limits.go`) and nowhere else. Same zero-value-trap class as `inbox.ModePrompt` (see its own doc comment in `pkg/inbox/inbox.go`) — check any new enum in this repo for a meaningful zero value before it ships.
- **Control plane and executor link share ONE TLS listener, routed by PATH.** Both are reached by an HTTP/1.1 `Upgrade` (`/control`, `/executor/connect`) hijacked by `pkg/upgradeconn` — a mux can't route the executor connection because rafikid becomes the one ASKING once it's up; there's nothing to route on until an HTTP request precedes the stream. After Upgrade, never read the underlying `net.Conn` — read the `upgradeconn.Conn`, whose hijack buffer holds anything pipelined behind the request (needed for both the control plane's auth+request case and the executor's h2 preface).
- **A child's task ledger is its own conversation, and only a USER credential keeps the per-user `mcp:user:<id>` ledger.** `ensureLedgerConversation` (`cmd/rafikid/task_ledger.go`) keys a fundi child's ledger by its engine-minted `SessionID` — the conversation UUID, empty until the engine has created it, so the caller asks again rather than inventing one — and any other kind (claude) by `external_ref = child_id`, client-driven: the same row the proxy's `X-Rafiki-Session` traffic creates, so exactly one of the two creates it and the other selects. A child credential reaches that ledger on every face (the `task_*` tools via `Controller.tasksFor`, the MCP face's `opts.Tasks` in `getServer`); the `mcp:user:<user-id>` row serves user credentials only. Reads never create a row: `ListTasks.owner_child_id` resolves through `conversationIDForChild` (`cmd/rafikid/controller_fundi.go`, a SELECT by `SessionID` or `external_ref`) and answers an empty list for an unknown child or one with no ledger yet. Pinned by `TestTaskLedgerFundiChildUsesItsSessionID`, `TestTaskLedgerClaudeChildEnsuresByChildID`, `TestTaskLedgerWiringUserCredentialKeepsThePerUserLedger` (`cmd/rafikid`) and `TestListTasksOwnerClaudeChildWithoutLedgerCreatesNoConversation`.
- **In `pkg/tasks` the memory store is atomic under its own mutex and Postgres is not, so the conformance suite structurally CANNOT catch a Postgres-only race.** Concurrency defects in the postgres store need a test in `postgres_test.go` that opens two transactions explicitly. `FOR UPDATE` locks only the rows it RETURNS, so a predicate in the SQL leaves concurrently-contested rows unlocked — filter in Go instead. And Go has no NULL, so `Assignee == ""` matches every unassigned in-memory row where SQL `= ''` matches none — guard empty-string arguments in both implementations.
- **Recovery reads `conversations.child.status`, and `exited` is the only terminal state.** A child that ended while a daemon was alive to record it says `exited` and stays dead across restarts. Anything else means the daemon died first and the child resumes exactly where its row stands.
- **Auto-resume and manual resume disagree about re-submission, on purpose.** The restart auto-resume builds the engine with `AutoResume` (`resumeClaimedWithAutoRecovery`), so `Engine.startupResume` → `agentloop.Resume` re-issues an interrupted turn (`Continue`, synthetic orphan results, immediate return on a clean tail); a MANUAL `rafiki resume` passes `autoResume=false` and skips `startupResume` entirely — it is interactive (re-open, view, kill again) and must never fire an LLM call. Pinned end to end by `TestDBChildState_AutoResumeReissuesMidTurnAfterCrash`, `TestDBChildState_AutoResumeIdleAfterGracefulRestart`, and `TestDBChildState_AutoResumesClaudeChildren` (`test/integration/restart_resume_test.go`).
- **Claude rows auto-resume at restart ONLY on `ownedByMe`, and the nudge signal is a label, not `last_status`.** A claude conversation never acquires a lease (only a fundi engine's build does), so for an adopted row the stale `updated_at` is the only evidence the original daemon is dead — the row's daemon_id classification is the fence (`launchRecoveryResume`, `cmd/rafikid/pending_resume.go`). The continuation prompt (`sendClaudeNudge`, shared with `deliverRateLimitResume`) fires only when the row says it was working: the row's status, or — for `shutting_down`, which the graceful path writes over idle and mid-turn children ALIKE — the `rafiki/pre-shutdown-status` label stamped at that one transition in `handleStatusChange`. The label gates a nudge, never a resume; the `last_status`-never-gates-recovery rule is untouched.
- **The executor gate on recovery is CLAUDE-ONLY, and the sweep fires on EVERY executor connection.** Only a daraja-hosted claude launch hard-requires a live executor (`darajaLaunchExecutor` refuses to resume a pinned claude child elsewhere), so that child pends (`pendingResume`) until its pinned executor connects; every `execPool.SetOnConnect` fires `sweepPendingResumes` (multiple executors are standard — the last connect satisfies the last child), gated on the boot walk's completion, and `Close`/`Kill`/`CloseAllExited` drop pending entries. A fundi child NEVER waits: its binding is lazy (starts unbound, binds on first tool use), so waiting would strand it on a daemon where nothing ever connects (the default-on local listener with zero enrolled executors).
- **A fake Anthropic seat must speak SSE.** A streaming Messages request answered with a plain-JSON (or any non-SSE) 200 body silently parses as an EMPTY message with NO error — the SDK's ssestream decoder skips every non-`data:` line and reports none — so `agentloop` reads it as `unexpected stop reason ""` and the turn fails. `test/integration`'s `fakeAnthropicServer` (script_child_test.go) has this shape: the turns it serves record `complete, 0 tokens, stop_reason NULL` in `conversation_turn`, and those tests stay green only because a failed turn settles on the child's EXIT, which is what the drivers wait for. The SSE seat in `restart_resume_test.go` is the working shape; use it whenever a test must assert on turn SEMANTICS rather than lifecycle.
- **A failed turn SURVIVES; a failed startup resume FATALS.** `Engine.runTurn`'s error branch emits `agent_error`, `AgentEnd`, and the child goes idle; `Engine.startupResume`'s error branch calls `e.fatal` — the child exits and `handleChildExit` persists `exited`. Consequence: restart the daemon while the provider is down and every recovered child exits after its resume retries exhaust, permanently orphaning rows the next boot will never resume (terminal status). Any change to one branch must justify why the other stays different — see `docs/plans/2026-10-01-restart-resume-consistency-design.md` G5.
- **The daemon's own shutdown persists NOTHING to child rows** (`c.stopping`) — the process is dying and its children die with it, so rows keep their live statuses and the next daemon resumes them, which is what makes a redeploy transparent. `last_status` is observability only and must never gate recovery.
- **One writer per conversation, and the guard is inside the append's own transaction.** `conversations.conversation_lease` restores the daemon isolation a shared `conversations.child` removed. `conv.Handle.Append` (`pkg/conv/append.go`) hands the write to `store.ConvBackend.Commit` (`pkg/store/convbackend.go`), which takes the conversation row `FOR UPDATE`, then `fenceLease` reads the lease row `FOR SHARE` in that same transaction, so a takeover's `UPDATE` blocks until the append commits and a stalled holder that wakes after takeover writes nothing — a monotonic fencing token is unnecessary. `conv.Handle.RetractHead` fences identically. `conversation_turn` writes are deliberately NOT fenced (append-only analytics).
- **`RAFIKI_DAEMON_ID` must be unique per running daemon, and is required in k8s.** `LeaseStore.Acquire`'s `OR holder = EXCLUDED.holder` clause lets a restarted daemon reclaim its own leases instantly; two daemons sharing one id reclaim each other's leases on every acquire and reproduce the split-brain the lease exists to prevent. A pod filesystem is ephemeral, so set the env var in the Deployment spec rather than relying on `<DataDir>/daemon-id`.
- **`RAFIKI_DAEMON_ID` cannot prove two rows are on the same machine — `ns_token` does.** On Linux it's the `/proc/self/ns/pid` link; on darwin it's `kern.boottime`, so every daemon on one Mac carries the SAME token since boot and it discriminates nothing there. `Forget` checks both columns before deciding a row belongs to the caller.
- **Boot-time orphan signaling needs BOTH `ns_token` and `daemon_id` — `ns_token` alone kills other daemons' children on one machine.** `recoverOne` SIGTERMs a row's recorded pid only when `rec.NSToken == c.nsToken` (is this pid trustworthy) AND `rec.DaemonID == c.daemonID` (is this child mine). Pinned by `TestRecoverOneDoesNotSignalAnotherDaemonsLiveChild` and `TestRecoverOneSignalsItsOwnRestartOrphan`.
- **A pinned child never changes machines, and restart recovery is not an exception — but it IS a resume.** `recoveryAction` returns `planResumeBound` for `workspace_mode` pinned (or absent/unrecognised). The stale workspace id is stripped while `rafiki/executor` survives, so `boundExecutor.doRecover` can re-provision on the SAME executor. Only an ephemeral child has both labels stripped and resumes unbound.
- **Child rows are shared across every daemon, so destructive writes are gated on `ownsChildRow` — which reads the `rafiki/daemon` LABEL, not the `daemon_id` column.** The gate stops a daemon from deleting rows belonging to a sibling still running. An exited child that was never re-persisted keeps its ORIGINAL pod's label and is uncloseable after a redeploy unless boot recovery's `AdoptOwnership` re-stamps `daemon_id` and the label together (never `status`, never `ns_token`). Closed rows are tombstones filtered by `List`; `Upsert` clears `deleted_at` unconditionally, so a tombstone must never be fed back through it.
- **Recovery is scoped by daemon ownership, and the gate's job is to stop the ATTEMPT, not to protect the inbox — the inbox is already safe on its own.** `childstoredb`'s `listSQL` has no `WHERE`, so every daemon sharing a database walks every row. `recoveryOwnership` classifies each from `rec.DaemonID` plus `LeaseStore.LiveConversations`; a `foreignLive` row loads into the store (visible in `rafiki list`) but is never resumed. The inbox is independently safe for a foreign live child: `OnConversationResolved` acquires the lease before `resetUnconfirmedOnOwnership`, and `holdsLease` gates `replayInbox`. This gate's own primary case is `c.daemonID == ""`, where `holdsLease` is skipped entirely and `recoveryOwnership` refuses every claimed row instead — keep it for that reason, since it reads the lease set once at startup and can't see a daemon that acquires afterward.
- **The Connect control plane is mounted INSIDE the proxy face, not beside it — there is exactly one mount per surface and a second one would shadow the first.** `cmd/rafikid/proxy.go` composes the routes into `server.Handler`, wrapped in the same `UserTokenAuth.Middleware` that protects `/v1/messages`. A `mux.Handle` for `/rafiki.v1.Control/` in main.go compiles and silently shadows that auth (ServeMux prefers the longer pattern). Caller identity arrives via `server.IdentityFromContext`; `connectLifecycle.Spawn` must read it, not hardcode `users.Identity{}`. Remote Connect is HTTP/1.1, not h2 (the shared listener advertises `http/1.1` only, since net/http can only hijack HTTP/1.1) — fine, since connect-go only refuses BIDI streaming below HTTP/2 and `StreamEvents` is server-streaming, but pinned by `TestStreamEventsSurvivesHTTP11ALPN` so it can't go vacuous.
- **Images travel end to end, and the middle of the pipe was the only text-shaped part.** Both ends already spoke blocks (`SendRequest.blocks`, `llm.Conversation.AppendUser`); the flattener, `inbox.Inbound.Text`, `agent_inbox.body`, and `Engine.HandlePromptID` needed `inbox.Attachment{MediaType, Data}` added beside the text. Images go FIRST in `llm.UserContent` (a model attends better to an image preceding the question about it), an attachment alone is a valid message (no text required), and the TUI stages a pasted PATH, never bytes — a terminal never sends image data through a bracketed paste (`^V` reads the clipboard directly instead; see the cockpit-tui skill). Rendering an attached image is a cockpit-tui concern (see that skill). The frame→frontend→engine→wire path is pinned whole by `pkg/fundi/attachments_test.go`. Outbound, the native `user_message` echo carries the images too (`Emitter.UserMessage(text, images)`, same order as `llm.UserContent`), and `eventconv.BlocksFromMsg` decodes stored image blocks for `GetHistory`. The echo is a durable event, so its image bytes are also written to `conversations.event_log`, a known second copy pending the event log redesign. EXCEPTION, the one silent drop: a STEER delivers text only — `frontend.go`'s `case "steer"` hands `HandleSteerID(id, message)` and drops the frame's attachments with NO log line (the prompt path warns when it cannot take them), and `HandleSteerID` has no attachment slot anyway. A submitter that steers with attachments loses them silently.
- **The event log is NOT the transcript, and two unrelated ordinal spaces meet in the cockpit.** `conversations.event_log` only begins when the event plane was deployed; `conversation_message` holds every message ever persisted, served by `GetHistory` (paging `conv.Store.Page`) and `eventconv.EventsFromNodes`. Folding history through `Session.Apply` (which stamps `conversation_message.ordinal`) would advance the session's cursor past the much-smaller `event_log.ordinal` space the focus stream resumes from — `Session.ApplyHistory` applies payloads WITHOUT touching the cursor for exactly this reason (`TestHistoryDoesNotMoveTheEventLogCursor`). The stream then resumes from the log head captured BEFORE the history fetch, so a turn landing mid-fetch can at worst duplicate, never gap.
- **`StreamEvents`' replay-to-live hand-off is exact only because each child's event-log ordinals are gap-free.** `delivery` (`pkg/connectapi/stream.go`) subscribes BEFORE replay, flushes headers at open, and keeps one per-child high-water mark of ordinals EXAMINED (sent or filtered out): a live durable event at or below it is a replayed duplicate and is dropped, one beyond it plus one is a `pkg/bus` drop and the missing range is backfilled from the log. A failed `Append` publishes without an ordinal and must never consume one, or every later live event for that child turns into a backfill read. A `floor` replays unnamed children found by `eventlog.Store.ChildrenSince`, but only ones `Lineage.Labels` still knows, so a closed child is never resurrected by the rails' 24h reconnect floor. Pinned by `pkg/connectapi/stream_handoff_test.go`; full rules in `docs/reference/control-protocol.md` "Replay and the hand-off to live".
- **A conversation's messages are a TREE, and a request names its parent instead of being compared against the stored history.** `conversation_message.ordinal` is now insertion order (gap-free, allocated from `conversation.next_ordinal` under the conversation row lock), not a position in the history; a node's identity is `path_hash = sha256(hash_version ‖ parent slot ‖ canon(role, content))` (`pkg/convtree`). Claude Code's own compaction, a rewind and a `/clear` are therefore ordinary tree shapes rather than ordinal collisions. `planAttach` (`pkg/capture/capture.go`) decides where a request hangs, first match wins: no `diagnostics.previous_message_id` → a pending `/clear`'s root, else an existing root equal to `messages[0]`, else a plain root; the id resolves and `messages[depth]` is the message that node holds (`store.SameMessage`) → attach the suffix there; the id resolves, verification failed and `messages[0]` reads as a summary → a `compaction_summary` root derived from that node; else the whole chain is matched by path hash and attached at the deepest hit (`fallback_count` + 1, WARN with the reason); else a new plain root. **The earlier replayed history is never compared**, so the client changing how it replays old messages cannot fork anything. A message's `content` still arrives as both a bare string and a block array — `Canon` and `headText` accept both. Model, cutover procedure and `rafikid tree check`: `docs/reference/conversation-tree.md`.
- **The `/clear` slash command opens a new ROOT of the tree, and the pending flag is consumed in the same transaction as that root.** `conversation.clear_pending` (migration 0049) is set by `CaptureStore.MarkClearPending` and consumed by capture's no-predecessor branch, which appends a root of kind `clear` derived from the current head (`ConsumeClearPending`, `pkg/store/tree.go`); the flag survives a chained request and is never consumed by a request that names a predecessor. A clear root's seed mixes in the node it was cut from, so two clears in a row are two distinct roots — without that, the second `/clear` would find the first clear's node and graft the new history under it (`convtree.RootSeed`, `TestTwoClearsAreDistinctRoots`).
- **fundi published only HALF the native event vocabulary — the missing half was the assistant's replies.** Switch arms with no caller are the shape of this bug; grep for callers when a vocabulary looks complete. Durable publication happens ONCE per completed turn, at a single site in `Engine.worker`'s `OnTurn`, because only one of `StreamEnd`/`AssistantTurn` is handed the provider response. `ContentBlockDelta` is still unpublished by fundi, so a fundi turn appears all at once rather than streaming.
- **Nothing drives a content event end-to-end through `StreamEvents` in tests** — the seam between synthetic-event unit tests and the fundi emitter is only ever exercised by hand against a real daemon. Budget for that when touching the event plane.
- **`anthropic.Message.ToParam()` goes through `AsAny()` and is unsafe on a mid-stream accumulated message.** `Message.Accumulate` only rewrites `ContentBlockUnion.JSON.raw` on `content_block_stop`, so `ToParam` (and anything fed from it) yields EMPTY blocks on a partial message even though the struct fields are correct. Read the flattened fields directly for a partial response instead.
- **`forget` was never forgetting — it is `close`, and it is the point of no return for CONTINUING a conversation, not for reading it.** `Controller.Close` drops the in-memory entry, the `conversations.child` row, and inbox rows — nothing references `conversations.child` by foreign key, so nothing cascades and `rafiki logs` still works afterwards. What it ends is resumption, since `resumeInternal` resolves its target from the store this deletes.
- **The Connect control plane is served only when the proxy face comes up**, so ANY proxy-listener failure surfaces as Connect-plane tests failing to reach the control socket — read the daemon's stderr before assuming a Connect regression.
- **`quota_status` resolves a child's owner USER ID on every path — spawn AND resume/recovery.** `agentRuntimeOptions`'s `ownerUserID` comes from the authenticated identity at spawn, and from `resumeOwnerUserID` at resume (the stored column, else the owner's username resolved through `users.Store.LookupUsername`, which is active-rows-only). An unresolvable name logs and continues unattributed rather than refusing the resume.
- **Owner attribution travels via `llm.NewConversation`, and `llm.Entrypoint` alone leaves a conversation unowned.** `fundi.Config.OwnerUserID` → `llm.NewConversation(c.OwnerUserID, "agent")` is the ONLY way `owner_user_id` is ever populated — the whole pipe is `Spawn`'s `owner.UserID` (or `resumeOwnerUserID`) → `agentRuntimeOptions` → `fundi.Config` → the row. Empty stays valid (an anonymous spawn is legitimate) but is easy to lose silently at any hop.
- **Every per-child deadline and the periodic budget/inbox reconciliations run on the `pkg/sched` scheduler, registered through `Controller.at` (`cmd/rafikid/timers.go`), and every callback tolerates its subject having vanished.** Grace (`armGrace`), heartbeats (`armHeartbeat`/`fireHeartbeat`, `heartbeat_sweep.go`), schedule fires (`armSchedule`/`fireSchedule`, `schedules.go`), the periodic reconciliations — the budget sweep and the inbox-retention sweep (`startPeriodicSweeps`, fixed keys `sweep:budgets`/`sweep:inbox`) — and jobwatch (`newControllerJobWatcher` sets `w.sched = c.sched`, so it registers one entry per watched job on the controller's SHARED scheduler) are all deadlines keyed by id: an arm REPLACES the pending job under the same key, and a callback whose child is gone, no longer in the expected status, or no longer owns the row returns WITHOUT re-arming. The proxy escalates every capture error to the turn: `failTurn` after `DecomposeRequest`/`AppendResponseMessage`, and on the upstream-error path `handleUpstreamError` re-fails the turn with `<reason>; decompose request failed: …`. Pinned by `TestCapturedClaudeSessionReplays`, `TestReplayTwiceAddsNoRows` (`pkg/capture`) and `TestMessagesProxy*Decompose*` (`pkg/server`).

Dropping the report is what wedged a claude child — its frame armed the gate, `flush` stops at the first unpersisted tag so no later report could unblock it, and `TurnEnd` stayed queued until the child exited (sentinel: a chat turn that never ends). The FORK's discriminator is family existence + `cc_is_subagent`; the synthetic CHILD's is that plus `DeclaresClientTools`. - **The self-kill settlement guard is audience-scoped and causality-based, not shape-based — and claude children never die "clean" when killed.** Claude Code catches SIGTERM and exits 143 with no signal, so a `signal == "" && exitCode == 0` clean-exit test misreads every SIGTERM'd claude as a foreign crash. The rule is `selfKillDispositionFor(mark, exitCausedByShutdown(res))`: `ShutdownResult.ByShutdown` is set BEFORE each rung that can kill (SIGTERM/SIGKILL, abandon, closing a `StdinStopper`), because `handleChildExit` reads it on `done`'s close and a post-hoc write would race it. Suppression is per-audience — a coordinator's `agent_kill` silences its parent's fragment; an MCP caller's kill excludes its own user from `notifyMCPSettled` while the parent still hears. A death the kill did NOT cause (a panic, a subprocess crash, a foreign SIGKILL) suppresses nothing. Tests exercising the MCP fan-out in parallel must use the real `mcpSettlements` registry with a unique user id — swapping the global races every lingering settle goroutine a parallel test leaves behind.
- **A spawn's pre-fill has TWO persisted shapes, picked per child by whether the MODEL's tool set offers `read`.** The tool-call shape: `fundi.PrefillPreamble` (r0, user) → r1 assistant `tool_use` blocks with ids `prefill_NNNN` (NULL usage — `SeedHistory` with `meta == nil`) → r2 user `tool_result`s; the task prompt lands as the NEXT user row and `mergeForRequest` merges r2+r3 on the wire. The text shape (a tool-less child — `noBuiltinTools` or an allowlist without `read`; the reads run through an internal `read`/`glob` reader `BuildRuntime` materializes, never offered to the model): ONE user row starting with `fundi.PrefillTextPreamble`, whose body carries one `=== <path> ===` section (spanned `lines a-b` for a bounded range or a proven page) per read with the numbered output verbatim — written in one atomic write, so it has no partial prefix. `classifyPrefill` (`pkg/fundi/prefill.go`) maps empty/r0/r0+r1/complete/tool-complete to `prefillEmpty/HasR0/HasR1/Complete/TextComplete` and re-runs or replays verbatim (persisted `history[i].Param`s pass `SeedHistory`'s idempotence check) — `SeedHistory` is per-row non-atomic, so the TOOL-call shape's partials are genuinely reachable, not defensive. The worker is GATED: `NewEngine` starts the goroutine but `worker()` blocks on `Engine.Start()`'s channel, which `BuildEngine` closes only after lease acquisition and boot-time `RepairOrphans` — and the repair itself never repairs `prefill_`-prefixed ids (completing an interrupted pre-fill is `prefillHasR1`'s job), pinned by `TestWorkerWaitsForStart`, `TestRepairOrphansSkipsPrefillIDs`, and `TestBuildEngineRepairsBeforePrefill` (`pkg/fundi`).

Pinned by `TestPrefillResumeDoesNotContinueCompletePrefill`, `TestPrefillResumeDoesNotContinueTextPrefill`, and `TestPrefillEmptyHistorySkipsResume` (`pkg/fundi`).

- **A script child's inbox delivery DEFERS to its Receive stream — never write a frame to a script child's stdin.** `deliverInbox` returns the `errInboxDeferred` sentinel for `kind: script` (checked FIRST, before the claude-abort guard), which leaves the batch PENDING — both `MarkSent` and `MarkConsumed` run only on success. Returning `(false, nil)` there would silently CONSUME the rows (the queue treats a nil-error non-ack as consumed-on-write), which is exactly the wave-2 review's F1 bug class. - **A script child's settle is its EXIT, and the reason word is the kind's semantics.** `scriptSettleFor` (`cmd/rafikid/script_runtime.go`): exit 0 → `done`, anything else → `failed` — and "exit 0" means `Signal == "" && ExitCode == 0`, because a signalled child reports ExitCode 0 with Signal set (pkg/child's Wait contract). - **Script output is published as coalesced durable `ScriptOutput` events, flushed before `child_exited`.** The coalescer (`cmd/rafikid/script_output.go`) buffers per child per stream, flushing at 4 KiB or 250 ms whichever first; a lone line over the bound splits at exactly 4 KiB at a rune boundary, and every chunk is `ToValidUTF8`-sanitized at ingestion (protobuf-go refuses a mid-rune string), so the contract is line-faithful for valid UTF-8, not byte-exact. The final flush runs BEFORE the exit event publishes, so a client backfilling from the event log sees the whole output before the exit. A script child's status is `running`, set once at spawn (`pkg/child.StateMachine.ForScript`), and output never moves it — only exit replaces it.
- **Recovery settles a LOCALLY hosted script child `failed` ("daemon restarted") instead of leaving it running-with-no-process.** `scriptNeedsRestartSettle` (`cmd/rafikid/load_children.go`) collects non-terminal script rows whose ownership is not `foreignLive` AND whose `rafiki/daraja-pgid` label is empty, and `loadChildren` settles them AFTER the whole walk — the settle fragment goes to the child's PARENT, and `ParentOf` needs the parent's row in the store first. A foreign-LIVE row belongs to another daemon hosting it right now; a terminal row settled when it exited.
