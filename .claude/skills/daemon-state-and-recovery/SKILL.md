# Daemon state, capture, and recovery

This is "what's durably true after a restart, and how does the DB prove it" —
the inbox's at-least-once vs. consume-once split, conversation leases and
daemon ownership, and how Claude Code's own threads/subagents get
reconstructed into rafiki's conversation model. Same discipline as
CLAUDE.md: rule + where it's enforced, no incident narration, prune when
stale.

- **`conversations.raw_http_request` stores bodies in JSONB, but LLM traffic is frequently not JSON.** `nilJSON` (`pkg/rawtrace/rawtrace.go`) wraps any non-JSON payload (SSE bodies, HTML error pages) as a JSON string before insert, or Postgres rejects the row. `RawTraceStore.Insert` is best-effort (logs and returns nil on failure), so a regression here is silent. When querying `resp_body`, expect either a JSON object or a JSON string holding raw text.
- **One credential scheme: `base64url(sha256(token))` in an indexed TEXT column, for both `users` and `executors`.** Not bcrypt — tokens are 256 bits of `crypto/rand`, so a work factor defends nothing, and bcrypt can't be indexed (every auth would be a full-table scan). `users.HashToken` and `executorsdb.hashToken` must stay identical; the `executors.credential_hash` column comment claiming "bcrypt/argon2 digest" has always been wrong.
- **`users` rows are TOMBSTONED, never deleted, and joins must be by id.** `username` is unique only among ACTIVE users (partial index `users_username_active`), so a query joining by name can return multiple rows — `pkg/insights/search.go`'s owner filter carries `ORDER BY created_at DESC LIMIT 1` for exactly this.
- **An auth failure and an auth OUTAGE are different answers on both surfaces.** `users.ErrNotFound` → 401/`ERR_AUTH_INVALID`; any other store error → 503/`ERR_INTERNAL`, never 401 — a 401 tells clients to discard their credential, so answering a DB blip with 401 logs out everyone at once. Never forward the store's error text to the peer (a pgx error carries the DSN). Same rule as `executors.IsTerminalAuthError` (executor-plane skill).
- **The daemon has no users until someone creates one, and that window is open on every listener.** With no active user, a TLS control connection is admitted WITHOUT a token and may send only `ctrl_user_create` — first writer claims the daemon (deliberate; bounded by a per-minute WARN and a logged peer address). `RAFIKI_CONTROL_LISTEN` without `RAFIKI_DB` is fatal at startup, so the listener can't sit in permanent bootstrap mode.
- **A hypertable with columnstore rejects `ADD COLUMN ... REFERENCES`, but accepts the same FK as a separate `ADD CONSTRAINT`.** `0019_user_attribution` does this for `conversation_turn.author_user_id`. Never "solve" this by dropping columnstore or leaving the column app-enforced.
- **`conversations.v_analysis` and `v_finding` do NOT depend on `v_conversation`** — they read `conversation_analysis`/`analysis_finding` directly (confirmed via `pg_depend`), so `DROP VIEW v_conversation CASCADE` reaches only `v_turn`. Two design docs in this repo claim otherwise; trust `pg_get_viewdef` over them. The view-body chain is 0007, 0008, 0011, 0019 — review all four before touching `v_turn`. `owner_canonical`/`owner_kind` no longer exist as of 0019 (superseded by a direct `users` join).
- **An `ON CONFLICT (cols) WHERE pred` arbiter cannot see rows that fail `pred` — the INSERT SUCCEEDS and creates a duplicate; it never errors.** `skills_name_active` is a partial unique index over `WHERE enabled`, so an insert over a DISABLED row finds no conflict. Any upsert over that table must handle the disabled row FIRST (refresh in place when the source matches), and a sync's `DO UPDATE SET` needs a `WHERE ... source = EXCLUDED.source` guard so it can't overwrite an enabled override from a different source. `SetEnabled`/`Delete` scope by current row state for the same reason (pinned across `pkg/skillsdb`'s test suite). Probe a scratch database before assuming an upsert design's error semantics.
- **A kill is not complete when `ch.Shutdown` returns — wait for `cm.Remove`.** Status only becomes `exited` when `handleChildExit` calls `MarkExited`, asynchronously on `monitorChild`'s goroutine. Any path reporting a kill as done, or touching on-disk state afterwards, must call `waitForChildRemoval` first. `Kill`, `Forget`, and `ShutdownAllChildren` all do this.
- **`ctrl_*` response payload shapes are not uniform — read `pkg/control/dispatch.go` before writing a client-side decode, never infer from a sibling verb.** `ctrl_conversation_stats`/`ctrl_conversation_export` send the domain value bare; `ctrl_conversation_search` wraps its rows in `{"rows": [...]}`. Build response fixtures from the shape `dispatch.go` marshals, and confirm against a live daemon.
- **Every `ctrl_*` response is capped at `protocol.MaxFrameBytes` (16 MiB) per frame.** A writer emitting a larger frame doesn't error cleanly — `FrameReader` returns `ErrFrameTooLarge`, the connection is torn down, and the client sees an unhelpful "connection closed". Any new handler returning unbounded-size data must clamp or size-check the payload — see `recentResponseBudget` (`ctrl_get_recent`) and `protocol.ErrPayloadTooLarge` (`ctrl_conversation_export`) for the two established patterns.
- **The event buffer only schedules now; persisted inbox rows are the batch, not `eventbuf.Delivery`.** `Push`/`PushNow`/`PushSteer` persist a row with the right `inbox.Mode` and decide *when* to ask for delivery — coalescing happens at flush over pending rows, not in-memory buffer state. Stickiness (a group holding any `ModeSteer` row delivers as a steer) is a property of the data now, so it survives a daemon restart. `Buffer.fire` must still run its flush callback with `b.mu` released — flush reaches `Controller.deliverInbox` → `sendFrame`, a blocking write, and pushing from inside that path would deadlock on re-entrant acquire.
- **Two of `inbox.Store`'s five mutating methods — `MarkSent` and `MarkConsumed` — take NO `childID`; the per-child scoping elsewhere is caller discipline, not interface-enforced.** `pkg/inboxdb`'s implementations run `UPDATE ... WHERE id = ANY($1)` against nothing but the row ids. What keeps them from crossing children in practice is entirely in `pkg/inbox/queue.go`'s `Queue`: `Consume`/`deliver` take the per-child lock and only ever pass ids sourced from that same child's own `Pending()`/`Coalesce()` output. A caller combining ids from two children finds no guard stopping it.
- **A fundi child is IN-PROCESS, which is why an inbox row is acked on DEQUEUE rather than on `sendFrame` returning — but a smaller crash window stays open right after the ack.** `Engine.worker`'s own comment names the residual gap between the ack and `agentloop.Run`'s `AppendUser` (a mutex-held stdout write plus a DB rollup with a 3s timeout) as seconds, not microseconds — a crash there loses an acked prompt with no durable trace. A `claude` child has no ack signal at all (`awaitAck` forced false for non-fundi kinds), so its queue doesn't survive a restart.
- **An acked prompt can be deterministically un-persisted, and that is intentional.** `agentloop.Run` calls `conv.RetractTailUser` when the first LLM call on a fresh message fails `llm.IsPromptTooLarge`. Since `Engine.worker` acks the inbox row BEFORE running the turn (a crash mid-turn must not replay a prompt already worked on), an oversized prompt ends up acked AND erased, leaving only an `agent_error` frame. Don't "fix" this by leaving such a row unacked — the prompt is deterministically oversized, so an unacked row is a poison pill that replays and fails forever. One loud failure beats an infinite loop.
- **`SpawnRequest.MaxDepth/MaxCost/MaxChildren` are pointers because zero is meaningful for all three — they collapse to plain values in `childstore.Session`, where `MaxCost == 0` means UNLIMITED, not "spend nothing".** Every comparison against a stored budget must be guarded by `if snap.MaxCost > 0` first, or every unbudgeted agent refuses its first spawn. The collapse happens in `grantedCost`/`grantedDepth`/`grantedChildren` (`cmd/rafikid/limits.go`) and nowhere else. Same zero-value-trap class as `inbox.ModePrompt` (see its own doc comment in `pkg/inbox/inbox.go`) — check any new enum in this repo for a meaningful zero value before it ships.
- **Control plane and executor link share ONE TLS listener, routed by PATH.** Both are reached by an HTTP/1.1 `Upgrade` (`/control`, `/executor/connect`) hijacked by `pkg/upgradeconn` — a mux can't route the executor connection because rafikid becomes the one ASKING once it's up; there's nothing to route on until an HTTP request precedes the stream. After Upgrade, never read the underlying `net.Conn` — read the `upgradeconn.Conn`, whose hijack buffer holds anything pipelined behind the request (needed for both the control plane's auth+request case and the executor's h2 preface).
- **In `pkg/tasks` the memory store is atomic under its own mutex and Postgres is not, so the conformance suite structurally CANNOT catch a Postgres-only race.** Concurrency defects in the postgres store need a test in `postgres_test.go` that opens two transactions explicitly. `FOR UPDATE` locks only the rows it RETURNS, so a predicate in the SQL leaves concurrently-contested rows unlocked — filter in Go instead. And Go has no NULL, so `Assignee == ""` matches every unassigned in-memory row where SQL `= ''` matches none — guard empty-string arguments in both implementations.
- **Recovery reads `conversations.child.status`, and `exited` is the only terminal state.** A child that ended while a daemon was alive to record it says `exited` and stays dead across restarts. Anything else means the daemon died first and the child resumes exactly where its row stands.
- **The daemon's own shutdown persists NOTHING to child rows** (`c.stopping`) — the process is dying and its children die with it, so rows keep their live statuses and the next daemon resumes them, which is what makes a redeploy transparent. `last_status` is observability only and must never gate recovery.
- **One writer per conversation, and the guard is in the INSERT statement.** `conversations.conversation_lease` restores the daemon isolation a shared `conversations.child` removed. Message appends carry an `EXISTS` clause checking the lease in the same statement as the write, so a monotonic fencing token is unnecessary — a stalled holder that wakes after takeover writes nothing. `conversation_turn` writes are deliberately NOT fenced (append-only analytics).
- **`RAFIKI_DAEMON_ID` must be unique per running daemon, and is required in k8s.** `LeaseStore.Acquire`'s `OR holder = EXCLUDED.holder` clause lets a restarted daemon reclaim its own leases instantly; two daemons sharing one id reclaim each other's leases on every acquire and reproduce the split-brain the lease exists to prevent. A pod filesystem is ephemeral, so set the env var in the Deployment spec rather than relying on `<DataDir>/daemon-id`.
- **`RAFIKI_DAEMON_ID` cannot prove two rows are on the same machine — `ns_token` does.** On Linux it's the `/proc/self/ns/pid` link; on darwin it's `kern.boottime`, so every daemon on one Mac carries the SAME token since boot and it discriminates nothing there. `Forget` checks both columns before deciding a row belongs to the caller.
- **Boot-time orphan signaling needs BOTH `ns_token` and `daemon_id` — `ns_token` alone kills other daemons' children on one machine.** `recoverOne` SIGTERMs a row's recorded pid only when `rec.NSToken == c.nsToken` (is this pid trustworthy) AND `rec.DaemonID == c.daemonID` (is this child mine). Pinned by `TestRecoverOneDoesNotSignalAnotherDaemonsLiveChild` and `TestRecoverOneSignalsItsOwnRestartOrphan`.
- **A pinned child never changes machines, and restart recovery is not an exception — but it IS a resume.** `recoveryAction` returns `planResumeBound` for `workspace_mode` pinned (or absent/unrecognised). The stale workspace id is stripped while `rafiki/executor` survives, so `boundExecutor.doRecover` can re-provision on the SAME executor. Only an ephemeral child has both labels stripped and resumes unbound.
- **Child rows are shared across every daemon, so destructive writes are gated on `ownsChildRow` — which reads the `rafiki/daemon` LABEL, not the `daemon_id` column.** The gate stops a daemon from deleting rows belonging to a sibling still running. An exited child that was never re-persisted keeps its ORIGINAL pod's label and is uncloseable after a redeploy unless boot recovery's `AdoptOwnership` re-stamps `daemon_id` and the label together (never `status`, never `ns_token`). Closed rows are tombstones filtered by `List`; `Upsert` clears `deleted_at` unconditionally, so a tombstone must never be fed back through it.
- **Recovery is scoped by daemon ownership, and the gate's job is to stop the ATTEMPT, not to protect the inbox — the inbox is already safe on its own.** `childstoredb`'s `listSQL` has no `WHERE`, so every daemon sharing a database walks every row. `recoveryOwnership` classifies each from `rec.DaemonID` plus `LeaseStore.LiveConversations`; a `foreignLive` row loads into the store (visible in `rafiki list`) but is never resumed. The inbox is independently safe for a foreign live child: `OnConversationResolved` acquires the lease before `resetUnconfirmedOnOwnership`, and `holdsLease` gates `replayInbox`. This gate's own primary case is `c.daemonID == ""`, where `holdsLease` is skipped entirely and `recoveryOwnership` refuses every claimed row instead — keep it for that reason, since it reads the lease set once at startup and can't see a daemon that acquires afterward.
- **The Connect control plane is mounted INSIDE the proxy face, not beside it — there is exactly one mount per surface and a second one would shadow the first.** `cmd/rafikid/proxy.go` composes the routes into `server.Handler`, wrapped in the same `UserTokenAuth.Middleware` that protects `/v1/messages`. A `mux.Handle` for `/rafiki.v1.Control/` in main.go compiles and silently shadows that auth (ServeMux prefers the longer pattern). Caller identity arrives via `server.IdentityFromContext`; `connectLifecycle.Spawn` must read it, not hardcode `users.Identity{}`. Remote Connect is HTTP/1.1, not h2 (the shared listener advertises `http/1.1` only, since net/http can only hijack HTTP/1.1) — fine, since connect-go only refuses BIDI streaming below HTTP/2 and `StreamEvents` is server-streaming, but pinned by `TestStreamEventsSurvivesHTTP11ALPN` so it can't go vacuous.
- **Images travel end to end, and the middle of the pipe was the only text-shaped part.** Both ends already spoke blocks (`SendRequest.blocks`, `llm.Conversation.AppendUser`); the flattener, `inbox.Inbound.Text`, `agent_inbox.body`, and `Engine.HandlePromptID` needed `inbox.Attachment{MediaType, Data}` added beside the text. Images go FIRST in `llm.UserContent` (a model attends better to an image preceding the question about it), an attachment alone is a valid message (no text required), and the TUI stages a pasted PATH, never bytes — a terminal never sends image data through a bracketed paste. Rendering an attached image is a cockpit-tui concern (see that skill).
- **The event log is NOT the transcript, and two unrelated ordinal spaces meet in the cockpit.** `conversations.event_log` only begins when the event plane was deployed; `conversation_message` holds every message ever persisted, served by `GetHistory`/`eventconv.EventsFromMessages`. Folding history through `Session.Apply` (which stamps `conversation_message.ordinal`) would advance the session's cursor past the much-smaller `event_log.ordinal` space the focus stream resumes from — `Session.ApplyHistory` applies payloads WITHOUT touching the cursor for exactly this reason (`TestHistoryDoesNotMoveTheEventLogCursor`). The stream then resumes from the log head captured BEFORE the history fetch, so a turn landing mid-fetch can at worst duplicate, never gap.
- **`conversation_message.ordinal = index-in-request` assumes a stable prefix, and Claude Code's own compaction breaks it.** Every proxied request replays full history from index 0; compaction rewrites message 0 to a summary and shifts everything after it, so a naive `ordinal = index` insert collides with a different pre-compaction row and drops the assistant response. `conversation.resume_from_ordinal` plus `conversation_message.kind='compaction_summary'` (migration 0029) fix this: `DecomposeRequest`'s `resolveHorizon` compares request message 0 against the stored row at the horizon; on a mismatch it tries a positional re-anchor before recording a new boundary. Nothing is ever deleted or renumbered. `store.Messages.Load` is NOT filtered by this horizon and must never be — `GetHistory`/`ctrl_get_recent`/fundi's own `loadHistory` all need the full pre-compaction history. A message's `content` arrives as both a bare string and a block array — Claude Code sends the compaction summary as the bare string, so any content parser here must handle both shapes or the horizon never advances and every compacted request fails with `ordinal already occupied by a different message`.
- **fundi published only HALF the native event vocabulary — the missing half was the assistant's replies.** Switch arms with no caller are the shape of this bug; grep for callers when a vocabulary looks complete. Durable publication happens ONCE per completed turn, at a single site in `Engine.worker`'s `OnTurn`, because only one of `StreamEnd`/`AssistantTurn` is handed the provider response. `ContentBlockDelta` is still unpublished by fundi, so a fundi turn appears all at once rather than streaming.
- **Nothing drives a content event end-to-end through `StreamEvents` in tests** — the seam between synthetic-event unit tests and the fundi emitter is only ever exercised by hand against a real daemon. Budget for that when touching the event plane.
- **`anthropic.Message.ToParam()` goes through `AsAny()` and is unsafe on a mid-stream accumulated message.** `Message.Accumulate` only rewrites `ContentBlockUnion.JSON.raw` on `content_block_stop`, so `ToParam` (and anything fed from it) yields EMPTY blocks on a partial message even though the struct fields are correct. Read the flattened fields directly for a partial response instead.
- **`forget` was never forgetting — it is `close`, and it is the point of no return for CONTINUING a conversation, not for reading it.** `Controller.Close` drops the in-memory entry, the `conversations.child` row, and inbox rows — nothing references `conversations.child` by foreign key, so nothing cascades and `rafiki history` still works afterwards. What it ends is resumption, since `resumeInternal` resolves its target from the store this deletes.
- **The Connect UDS is served only when the proxy face comes up**, so ANY proxy-listener failure surfaces as Connect-plane tests failing on a missing `connect.sock` — read the daemon's stderr before assuming a Connect regression.
- **`quota_status` resolves a child's owner USER ID on every path — spawn AND resume/recovery.** `agentRuntimeOptions`'s `ownerUserID` comes from the authenticated identity at spawn, and from `resumeOwnerUserID` at resume (the stored column, else the owner's username resolved through `users.Store.LookupUsername`, which is active-rows-only). An unresolvable name logs and continues unattributed rather than refusing the resume.
- **Owner attribution travels via `llm.NewConversation`, and `llm.Entrypoint` alone leaves a conversation unowned.** `fundi.Config.OwnerUserID` → `llm.NewConversation(c.OwnerUserID, "agent")` is the ONLY way `owner_user_id` is ever populated — the whole pipe is `Spawn`'s `owner.UserID` (or `resumeOwnerUserID`) → `agentRuntimeOptions` → `fundi.Config` → the row. Empty stays valid (an anonymous spawn is legitimate) but is easy to lose silently at any hop.
- **`heartbeatInterval` cannot be finer than the sweep ticker.** Heartbeat delivery rides `startSweeper`'s ticker, so the configured interval is quantized to it — `interval == tick` is the worst setting, since `due()` firing on `>=` flips the cadence between one and two ticks on drift. Any cadence change must move the ticker, not just the interval; a coarser tick trades latency for DB load (`sweepBudgets`/`sweepHeartbeats` each query per working child).
- **Claude Code runs every thread of one session under ONE `X-Rafiki-Session`, set per PROCESS, not per thread** (main thread, every Task subagent, the titler, the quota probe).
- **`cc_is_subagent` is present-only-when-true, and is ALSO the routing conjunct**: only a flagged, predecessor-less request on an EXISTING session family is treated as an independent thread founder. A parser keying on a literal `false` never fires; a router keying on family existence alone forks the main thread's post-compaction continuation onto a branch.
- **`cc_is_subagent` means "not the main thread", NOT "Task subagent" — the discriminator for a RAIL ROW is `claudethread.DeclaresClientTools`.** Claude Code also stamps the flag on the per-tool-call haiku one-shots it fires for WebFetch/WebSearch summaries, which correctly fork (a 2-message helper landing on the root would collide with the main thread's ordinals) but aren't agents, since neither can call a tool. The predicate keys on a `tools[]` entry carrying `input_schema`, separating a client tool from an Anthropic server one.
- **A tool-less branch's spend folds into its PARENT, via `SubtreeSelector.ExternalRefPrefixes`.** The third selector route matches branch conversations by the `<childID>:` prefix; `costsFor` attributes a branch to the parent only when NO child claims it, checked against the whole childstore rather than a possibly-filtered snapshot, or a filtered-out real subagent's cost slides onto its parent. `starts_with`, never `LIKE` — a child id contains `_`, which LIKE reads as a wildcard.
- **`diagnostics.previous_message_id` is ONE hop of the thread chain, family-scoped.** The chain lives in `conversation_turn.response_message_id` (migration 0030), written by `RecordThread`; the canonical response id is read by `capture.MessageIDFromCanonical`. Founding turns route to their own branch at `beginCapture` with a pre-minted turn id.
- **`conversations.child` has no CHECK on `status` and a nullable `pid`**, so a process-less synthetic child (for a Claude Code thread) faces no schema rejection — the real constraints are `kind`/`spawned_at` NOT NULL and the `conversation_id` FK.
- **`RenderRecent` has returned nil since B4** — rendered reads for a resolvable child are served from `conversation_message` (`Controller.dbRecent`, routed by resolvability, not kind).
- **`ON CONFLICT (conversation_id, ordinal) DO NOTHING` is correct for request messages and was corruption for responses.** Request rows stay lenient (first-seen wins on replay); response appends are STRICT (`ErrOrdinalOccupied`, non-retryable) — never close this asymmetry from either side.
- **`authorAttribution` (`pkg/server`) is the single decision point both capture entry points route through** — it was a hardcoded `"human"` literal at both, so every Claude Code subagent turn was misattributed. Any new capture entry point must decide `author_kind` explicitly, never default it.
- **Two independent witnesses to the subagent tree join on `message.id`**: the proxy sees HTTP and knows the thread; the child supervisor sees stream-json and knows the spawning `parent_tool_use_id` (`SubagentFrame`). The supervisor's `OnSubagent` hook fires ASYNCHRONOUSLY per qualifying frame and dedupes after the DB lookup, since each frame carries a NEW message id and a pre-lookup dedupe is impossible.
- **The label `rafiki/native-subagent` is spelled in two packages that cannot import each other** (`labelNativeSubagent` in `cmd/rafikid`, `rail.NativeSubagentLabel` in `pkg/tui`) — grep the other side before changing either.
- **A thread's founding request never shares the main thread's ordinal space: the proxy pre-mints its turn id and routes it to its own branch**, creating the synthetic child in `beginCapture` on the founding request itself. The FORK's discriminator is family existence + `cc_is_subagent`; the synthetic CHILD's is that plus `DeclaresClientTools`. An unflagged auxiliary founder (the titler, the quota probe) keeps the root-row behavior and fails LOUDLY on collision instead.
- **The self-kill settlement guard is audience-scoped and causality-based, not shape-based — and claude children never die "clean" when killed.** Claude Code catches SIGTERM and exits 143 with no signal, so a `signal == "" && exitCode == 0` clean-exit test misreads every SIGTERM'd claude as a foreign crash. The rule is `selfKillDispositionFor(mark, exitCausedByShutdown(res))`: `ShutdownResult.ByShutdown` is set BEFORE each rung that can kill (SIGTERM/SIGKILL, abandon, closing a `StdinStopper`), because `handleChildExit` reads it on `done`'s close and a post-hoc write would race it. Suppression is per-audience — a coordinator's `agent_kill` silences its parent's fragment; an MCP caller's kill excludes its own user from `notifyMCPSettled` while the parent still hears. A death the kill did NOT cause (a panic, a subprocess crash, a foreign SIGKILL) suppresses nothing. Tests exercising the MCP fan-out in parallel must use the real `mcpSettlements` registry with a unique user id — swapping the global races every lingering settle goroutine a parallel test leaves behind.
- **A spawn's pre-fill is three persisted rows with a pinned shape, and recovery must recognise every prefix of it.** `fundi.PrefillPreamble` (r0, user) → r1 assistant `tool_use` blocks with ids `prefill_NNNN` (NULL usage — `SeedHistory` with `meta == nil`) → r2 user `tool_result`s; the task prompt lands as the NEXT user row and `mergeForRequest` merges r2+r3 on the wire. `classifyPrefill` (`pkg/fundi/prefill.go`) maps empty/r0/r0+r1/complete to `prefillEmpty/HasR0/HasR1/Complete` and re-runs or replays verbatim (persisted `history[i].Param`s pass `SeedHistory`'s idempotence check) — `SeedHistory` is per-row non-atomic, so partial shapes are genuinely reachable, not defensive. The worker is GATED: `NewEngine` starts the goroutine but `worker()` blocks on `Engine.Start()`'s channel, which `BuildEngine` closes only after lease acquisition and boot-time `RepairOrphans` — and the repair itself never repairs `prefill_`-prefixed ids (completing an interrupted pre-fill is `prefillHasR1`'s job), pinned by `TestWorkerWaitsForStart`, `TestRepairOrphansSkipsPrefillIDs`, and `TestBuildEngineRepairsBeforePrefill` (`pkg/fundi`).
- **A pre-fill-shaped or empty history must NEVER reach `agentloop.Resume` at worker start.** On a 3-row prefill tail, Resume's orphan analysis sees r1's ids resolved, r1's empty stop reason makes `lastAssistantClean` nil, and the model is called with the files and no task; on empty history Resume errors outright. `worker()` (`pkg/fundi/engine.go`) skips `startupResume` for every state except `prefillNone` on a non-empty history — and `prefillComplete` skips even when the engine was rebuilt with no `Prefill` configured (the shape, not the config, is the discriminator). Pinned by `TestPrefillResumeDoesNotContinueCompletePrefill` and `TestPrefillEmptyHistorySkipsResume` (`pkg/fundi`).
- **Pre-fill provenance is the `prefill_` id prefix plus NULL usage on r1 — cost math and `ProviderGuard` evidence depend on "not reported" staying NULL, never zero.** Pinned by `TestPrefillSyntheticRowUsageIsNull` (DB) and `TestPrefillAssistantRowHasNoUsage` (in-memory).
