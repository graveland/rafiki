# The cockpit (pkg/tui)

Two focus panes, one renderer per child, and two independent event feeds that
must never cross-pollinate their cursors. Same discipline as CLAUDE.md: rule
+ where it's enforced, no incident narration, prune when stale.

- **The cockpit's textarea is emacs-keymapped, so a GLOBAL binding is a key you can no longer type.** `bubbles/v2/textarea`'s `DefaultKeyMap` claims `pgup`/`pgdown`/`shift+up`/`shift+down`/`ctrl+n`/`ctrl+p`/`ctrl+f`/`ctrl+u`/`ctrl+k`/`ctrl+a`/`ctrl+e` and more — `keys.go` carries a flattened copy and `TestNoGlobalBindingStealsATextareaKey` fails the build on a collision; re-check it when bubbles is upgraded. `ctrl+b`/`ctrl+g`/`ctrl+d` are grandfathered exceptions and unusable while typing.
- **The rail sizes to its CONTENT, never to the window, and a modal hides it entirely.** `railWidthFor` measures the longest row (cursor, indent, glyph, name, badge, cost), floored at `railMin` and capped at `railMaxPct` of the window. `Cockpit.railCols` is the single answer to "how wide is the rail", returning 0 when `form`/`picker` is up.
- **A model that cannot tool-call is filtered OUT of the cockpit's model lists by default, and "unknown" is not "cannot".** `modelView.toolsOnly` defaults true (`^T` reveals the rest). `toolsKind` returns UNKNOWN for a nil `supported_parameters` list — every locally-served model has no catalog entry at all — and unknowns are KEPT, same as `visionKind`'s. A filter reading nil as "no tools" hides the entire local fleet.
- **The model detail block is FIXED-POSITION, fixed-HEIGHT, and shared by both views** (`modelDetail`, one function for the form and the picker). Every field keeps its column whether or not it has a value (absent reads "—"), so glancing at the same spot twice always finds the same fact. It always occupies `detailHeight` rows even with nothing highlighted, so the list above it doesn't reflow as the cursor moves.
- **An unwidthed `bubbles` textinput renders a ONE-CHARACTER placeholder.** `placeholderView` sizes its buffer to `Width()+1` and early-returns having emitted only the first byte, so `"(auto)"` renders as `"("`. Call `SetWidth` on every textinput; `pkg/tui` re-sizes them to the pane on each render.
- **The filter+sort panel is VERTICAL — one row per field.** A horizontal band of cells overflowed any terminal under ~140 columns and made row count depend on cell labels. `queryWindow` keeps a few rows of the list visible underneath, since a filter whose effect you can't see is the thing the panel exists to avoid.
- **Constraints and ordering are SEPARATE, which is why `^S` opens a filter+sort panel and not a multi-key sort.** Sort priority alone cannot express a constraint ("ctx ≥1M and price ≤$2" removes rows; a sort order does not). `^R` keeps the old one-key cycle for the common case.
- **`tea.KeyPressMsg.String()` spells space as `"space"`, so `case " ":` is a silently dead binding.** Any new key case wants a test that drives the real `handleKey` path, not the handler's internals.
- **Model columns are pinned plus ONE, chosen by the sort** (`modelSort.column()` returns the extra column a sort makes worth showing). Everything sparse lives on the detail line for the highlighted row instead of costing width on every row. Absence-sorting itself (an unscored model sorts LAST, never as zero) lives in `pkg/modelquery` — see the model-catalog-and-routing skill.
- **One renderer per child (`pkg/tui/pane.go`), never one shared** — a shared renderer painted one child's half-finished paragraph into another child's pane before. Scroll position lives on `paneState`, not on `session.Session` (a pure event state machine).
- **`viewport.SoftWrap` is OFF and `pkg/tui`'s renderer wraps instead — do not turn it back on.** The viewport re-wraps EVERY line on every `Update` AND `View`; measured cost with it on vs. off was orders of magnitude apart on a large transcript, enough that a held arrow key queued redraws faster than the terminal could draw them. `renderer.Lines` wraps with `ansi.Wordwrap`/`ansi.Hardwrap` and repeats each block's gutter prefix on continuation rows. The renderer's cache is keyed on width (a resize invalidates it once, not per keystroke); `paneState.linesFor` skips the rebuild entirely when the transcript hasn't changed.
- **The focus ring is TWO stops, not three.** A separate transcript pane existed only to give a scrolling viewport its own keymap while the input textarea held every plausible scroll key; the input pane now scrolls the transcript directly (PgUp/PgDn, home/end outright; ↑/↓ shared via a `ta.Line()` before/after comparison). The cockpit holds TWO MODES and nothing between them: BROWSE (rail on screen AND focused) and TALK (full width, keys in the input). `leaveRail` hides the rail on every exit — ⏎/esc/⇥-out alike — because a rail drawn beside an unfocused input is the state that made focus ambiguous; ⇥ reveals it focused, `^R` is the only unfocused reveal (the watch-mode pin), and even that pin ends at the next visit to the rail (`TestEveryRailExitHidesTheRail`, `TestRailPinEndsAtTheNextVisit`).
- **The focus subscription FOLLOWS the view; browsing is live, rest-gated.** `Cockpit.viewing()` — the rail cursor while the rail holds focus, the committed agent otherwise — is what the conversation pane renders, and the ONE focus subscription moves to that child: `previewSettle` opens it once the cursor rests (`previewTickMsg` carries the `selectedSeq` it was armed under; a stale seq means the cursor moved on and a newer tick owns the action), and `historyMsg` opens the stream for the VIEWED child resuming from the fetch's LOG watermark (never a conversation ordinal — see `Session.ApplyHistory`'s doc). ⏎ and every rail exit (esc, ⇥ out of the ring) route through `leaveRail`, which hands the keys to the input and returns the subscription to the committed agent; committing to the already-viewed row is free (`openFocus`'s owner check). What keeps this off one-stream-per-keystroke is the rest gate — NOT a refusal to subscribe: a stream move is O(1) plus O(delta), where re-reading the transcript (`GetHistory`, one unpaginated query over the whole conversation — the most expensive RPC this client issues) would cost the whole conversation per rail event. A moved-away child's session KEEPS the cursor its feed advanced, so returning resumes from there and replays nothing twice. Fetches stay guarded by `historyInFlight` (ApplyHistory bypasses the ordinal cursor; two responses double every block), and while browsing the streamed session is the VIEWED child's, so `applyEvent`'s send-ack echo (`c.pending`) still checks `c.focused()`. Displayed is read: the badge clears only for the child actually under the cursor, and everything the readouts, status line and task box show follows `viewing()` too, or the chrome describes a different agent than the transcript beside it.
- **Rail visibility below two rows is a LOOK, not a gate — `railCols()` is the single visibility authority.** It returns 0 for a modal, `railHidden`, `Len()==0`, or `Len()<2 && !railPeek`; `renderRail` renders whatever it's given. `^R`/`⇥` peek-reveal a one-row rail; a peek only renders while it has a row, and the rail only enters the focus ring when `railCols()` would draw it.
- **Three ways the cockpit tells you where you are, because each one alone was missed.** A reversed footer badge AND an accent edge on the focused pane (naming it in a grey footer line alone wasn't noticed, since that's not where the eye is); a bottom-right scroll readout using `paneState.contentLines` (not the viewport's count, which includes bottom-anchor padding); and transcript weight by GUTTER, never background, since an agent's prose (the scarce thing) needs the solid `▌` and tool output (most of the screen on a working agent) needs none.
- **The cockpit cannot draw images, and the reason is the CELL GRID, not the ANSI layer — but Kitty's Unicode placeholder protocol routes around it.** bubbletea v2's `Cell` is one grapheme plus a style; a graphics escape written into a `View` is parsed into cells and dropped, with no error. The way through is out-of-band transmission (`tea.Raw`) plus placement via ordinary printable runes (Kitty's `kitty.Placeholder`, U+10EEEE + diacritics), which pass through a cell renderer untouched. Until built, `session.ImagePlaceholder` names the image so a block never renders as nothing. (The data model for how an image reaches the cockpit at all is in the daemon-state-and-recovery skill.)
- **A bracketed paste's line breaks are CARRIAGE RETURNS, not newlines.** `strings.Count(content, "\n")` undercounts a real multi-line paste, so it can sail under a fold threshold and unroll into the input box uncapped. `normalizeNewlines` folds CRLF and bare CR to LF before counting AND before storing — an agent must never receive a prompt with carriage-return line breaks either.
- **The input box has DYNAMIC height, so `bodyHeight` must subtract `ta.Height()` rather than a constant.** `bubbles`' textarea grows itself (`DynamicHeight`); a fixed subtraction overlaps the transcript by exactly the rows the box gains, invisible until someone types a long prompt.
- **`ToolCall.HasResult` is not `Result != ""`.** A tool can legitimately return nothing, and a call interrupted before producing a result is otherwise indistinguishable from a silent success. `attachToolResult` sets the flag explicitly; the renderer draws ✓ only when it's set and `⋯ no result` otherwise.
- **A tool's OUTPUT rides a `UserMessage` carrying a `tool_result` block, both live and in history — `ToolExecutionEnd` has no room for it.** Without publishing it, a live viewer sees every call's arguments and its ✓/✗ but never what it returned, appearing only on reattach. `Emitter.publishToolResult` publishes the same shape `eventconv.EventsFromMessages` produces, so a live viewer and a replayed one converge on one code path.
- **Never DOWNGRADE a tool call's failure.** `tool_execution_end` is the more direct witness (it carries the tool's own error); only ever set `IsError` true from a stored block's value, never overwrite an existing true with a missing/false one.
- **Tool RESULTS arrive on the user message, not the assistant one, and `TextFromContent` reads text blocks only.** Anthropic puts `tool_result` in the USER turn following the assistant's `tool_use`, so flattening content to text drops every tool output and renders an empty user bubble instead. Results are routed onto the call they answer by searching assistant blocks backwards (parallel tool use answers several calls in one block); a results-only message appends no block at all. `ToolCall.Input` must be populated too, or a call renders with no argument — the difference between watching an agent work and deciding whether to abort it blind. `applyToolStart` must not append unconditionally once the assistant message naming the `tool_use` is published BEFORE the tool runs, or every call duplicates.
- **A `bubbles` textarea is constructed BLURRED, and its `Update` returns immediately while it is** — an unfocused textarea silently swallows every printable key with no error. Every focus change must go through one place that sets both the ring and `ta.Focus()` together; a bare assignment re-opens the bug. Second-order: the textarea's own `InsertNewline` is bound to `enter`/`ctrl+m`, the same byte as Send, so a send-on-`⏎` input needs an explicit alternate newline key (`^J`/LF) since `⇧⏎` alone only works on Kitty-protocol terminals.
- **An empty transcript is a STEADY state, not a connection state.** `renderer.Lines` returns no lines for no blocks; the shell (which knows whether a stream is open) renders the empty case, not a hardcoded "Connecting…" — every freshly created agent has an empty log until it's asked something.
- **Tool output is not markdown and must never go through glamour.** glamour joins consecutive newline-separated lines into one CommonMark paragraph, collapsing a 500-line grep into one ~6000-column line. `renderAssistant` splits the RAW result for tool output; assistant PROSE still goes through glamour.
- **`session.Finalized` means "this block can never change again", and an assistant block does NOT qualify until its tool calls resolve.** The renderer caches every block below the watermark exactly once — finalizing early freezes a block on screen with no duration, no output, `⋯ no result` forever, since `tool_execution_end`/`tool_result` arrive AFTER the assistant message. `Block.Settled` and `recomputeFinalized` fix this; `settleAll` (on `turn_end`, `child_exited`, errors) is the required anti-stall guard, since one unanswered call would otherwise park the watermark forever and force every later block to re-render on every tick.
- **The cockpit has TWO event feeds, and the streamed session's ordinal cursor must be fed by exactly one of them.** The rail stream (six small types) and the focus stream (unfiltered) are independent goroutines writing one cockpit with no ordering between them. `Session.Apply`'s dedup is only sound within a single ordered feed, so rail events go through `applyRailEvent` and STOP there; focus events go through `applyEvent`, which applies only to the subscription owner (`focusChild` — the viewed child while browsing) and folds into the rail. The forbidden direction is rail → session: a rail-delivered event one ordinal ahead of the focus stream's own message can advance the cursor past a message never actually applied, silently eating it. Pinned by `TestRailDeliveryAheadOfFocusDoesNotEatTheUserMessage` and `TestRailEventsDoNotAdvanceTheSessionCursor`.
- **A message case with no producer is dead code, and the rail/focus split shipped exactly that way.** `waitForEvent` returned the same message type for both channels, so `case railEventMsg:` was unreachable in production even though tests constructed it directly — the suite stayed green while the feature was broken. Lesson: grep for a producer before trusting a vocabulary that looks complete; pin plumbing through the real channel path, not by hand-constructing the message. `rafiki watch` exists to see this class of gap from the outside.
- **Everything drawn as transcript content goes through `sanitizeControlChars` first** — tool results, tool arguments, and prose quoting them. The renderer's wrapping is ANSI-aware by design (to preserve glamour's styling), which also preserves a hostile tool's `\r`-repainting escape sequences unless stripped. Tests should assert the INPUT's escape fragments are gone, not that no `\x1b` survives at all (lipgloss's own styling legitimately carries escapes).
