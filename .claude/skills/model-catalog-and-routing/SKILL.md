# Model catalog and routing

The catalog only ever knows what OpenRouter tells it, most callers need to
treat "unknown" and "no" as different answers, and the provider cache guard
is observational because the catalog can't answer the caching question
directly. Same discipline as CLAUDE.md: rule + where it's enforced, no
incident narration, prune when stale.

- **An in-band SSE `error` event never becomes a typed `*anthropic.Error`** — the SDK wraps the raw JSON body in a plain `fmt.Errorf`, so it sails past every retry seam unless explicitly classified. `llm.ParseStreamError`/`llm.IsTransientStreamError` (`pkg/llm/streamerr.go`) recover the embedded payload (`timeout_error`, `overloaded_error`, `api_error`, or code ≥500 → transient); `agentloop.isRetryable` consults them. An in-band `rate_limit_error` is NOT transient-classified — it routes to `sendStreaming`'s rate-limit loop instead (`llm.IsRateLimitStreamError`), mirroring the typed-429 exclusion. Any new classifier must go through these, not string-match the wrapper — and never stringify an `*anthropic.Error` directly (`Error()` dereferences nil Request/Response on a status-only value).
- **The provider cache guard (`routing.ProviderGuard`) is observational, not a catalog lookup, and inert without capture.** OpenRouter's `supports_implicit_caching` flag doesn't correlate with real cache behaviour (see README), so the guard learns from observed `cache_read_tokens` instead. It qualifies a miss using `prefix_hash` and conversation id, both capture-only — with capture disabled nothing qualifies as evidence and it ejects nothing, by design (no evidence beats false evidence). Pinned by replay tests over real traffic in `pkg/routing/testdata/` — don't loosen the qualification rules to "fix" this.
- **The guard is also the one holder of operator bans, so it is NEVER nil in the daemon.** `RAFIKI_PROVIDER_GUARD=off` means `SetObserve(false)` (no automatic ejection), not a nil guard — a nil guard would silently drop every `rafiki providers ban`. A ban is reason `operator` under model line `routing.AllModelLines` (`*`), exempt from `maxEjectedPerModelLine`, zero expiry = until lifted; `Ban`/`Lift` write the sink FIRST and fail on error (automatic ejections swallow sink errors). The durable log is latest-row-wins: `EjectionStore.Active` must pick the newest row per `(provider, model_line)` BEFORE filtering expiry/`lift`, or an already-expired lift row hides itself and the lifted ban resurrects on restart — pinned by `TestEjectionStoreLiftSupersedesBan` (`pkg/ejection`).
- **`ModelCatalog` (`pkg/routing/orcatalog.go`) only ever knows OpenRouter ids** — it has no source of truth for a local/custom provider's model at all. A provider can declare `[providers.<name>.models.<alias>]` naming a short alias and optionally its `context_window`. `Set.Split` substitutes the alias's real id transparently for every sender, but `Controller.ContextWindow`/`ModelInfo` must look the alias up by the RAW, pre-substitution local id (`providers.SplitRaw`) — calling `Set.Split` first finds nothing, because by then the id is already resolved.
- **`expiration_date` is a FORWARD warning and needs an upper bound.** OpenRouter delists rather than leaving a model listed and expired, and some carry a sentinel far-future date meaning "no planned removal" — `expiryWarning` says nothing beyond a year out. `created` is OpenRouter's LISTING date, not the model's release date.
- **The three `artificial_analysis` indices are third-party CLAIMS, arrive TOGETHER, and are absent for most of the catalog.** A row with one has all three, shown side by side (only meaningful read against each other). Absent means UNSCORED and sorts LAST, never as a zero — every locally-served model is unscored. `knowledge_cutoff` is a DIFFERENT axis from `created`.
- **A descending sort must NOT invert the ABSENCE verdict** — `compareField`'s presence check returns unflipped from `sortModels`. An absent value is not "the largest", it's no answer, so it sorts last in both directions; flipping it puts every unscored model at the top of "smartest descending". Two absent values TIE and fall through to the next key. Bounds follow the opposite rule: `bound.admits` ADMITS a row the catalog can't answer for, since every locally-served model has no price, context, or score.
- **`ModelCatalog` throws away most of what OpenRouter sends, and two dropped fields are the only source for "has vision".** `orModel` decodes `name` and `architecture.input_modalities`; `output_modalities`/`supported_parameters`/`canonical_slug` are still dropped. Empty `input_modalities` means UNKNOWN, never "text-only" — every locally-served model has no catalog entry at all, so a vision filter reading empty as "no vision" hides the whole local fleet. Enumerate with `Rows()`, never per-id `ContextWindow`/`Pricing` calls (each takes the mutex).
- **`pkg/modelquery` is the ONE home for the catalog's three absence rules** — a bound admits a row the catalog can't answer for, an absent value sorts LAST in both directions, and unknown tool/vision support is KEPT. `pkg/tui/modelquery.go` keeps only presentation and delegates the rest. `pkg/fundi/tools` deliberately does NOT import `pkg/modelquery` (would drag protobuf into every binary linking a tool registry) — it keeps its own copy of the accepted sort keys and sort direction, kept in step only by `TestEveryToolSortKeyResolves`/`TestSortDirectionWordMatchesBiggerIsBetter` in `cmd/rafikid`. Add a sort key and touch both.
- **`agent_models` with NO arguments returns a SUMMARY, not a list.** The live catalog is 300+ models; flattening every row to a bare id fills an agent's context and tells it nothing about cost. A bare call reports count plus distribution (price range/median, context range, tools/vision counts, how many carry scores); rows only come from a narrowed query, capped by `limit` (default 20, max 50). A constrained query matching ZERO rows gets the distribution plus a diagnostic naming the excluding bound — describing an empty slice tells the agent nothing to re-aim with.
- **`controllerSpawner.Models` reads `ListModelRows`, never `ListModels`.** The row path is served from the already-warm routing catalog and applies `filterRowsForKind`, so a `claude` child is never offered an OpenRouter id it can't resolve. `Controller.ListModels` survives only for the frozen framed verb `ctrl_list_models`.
- **The picker's `scored` bound stop is the ONE exception to admit-unknowns.** It maps to `modelquery.Bound.RequirePresent` — the only way to ask for benchmarked models only. A numeric minimum can't substitute, since bounds admit unscored rows deliberately elsewhere (`TestBoundsAdmitModelsTheCatalogCannotAnswerFor`); `TestScoredStopExcludesUnscoredModels` pins the exception and its sibling test keeps it from leaking into price/context bounds.
- **Every `llm.Client` in the daemon shares ONE `*routing.ModelCatalog` — pass `llm.WithCatalog`, never let a daemon-side client build its own.** The instance is `Controller.catalog` (main.go builds one and hands it to the proxy face and `SetCatalog`); in-process fundi children get it through `RuntimeOptions.Catalog` → `Config.Catalog`, set once in `agentRuntimeOptions` (covers spawn, resume and startup recovery). A client built without it fetches OpenRouter's whole model list itself and holds its own copy for its TTL — N children, N fetches and N copies of the same ~MB. nil stays legal and means "the client builds its own" — the standalone `rafikid fundi` process has no daemon catalog — pinned by `TestBuildEngineUsesSharedCatalog`/`TestBuildEngineWithoutSharedCatalogBuildsOwn` (`pkg/fundi/config_test.go`) and `TestAgentRuntimeOptionsSharesControllerCatalog` (`cmd/rafikid/agent_runtime_test.go`). The older sibling: `Controller.ListModelRows` takes OpenRouter rows from the catalog instead of `models.loadOpenRouter`'s own HTTP fetch + disk cache; re-adding that to a daemon path reintroduces a second cache with a different TTL.
- **Kind scoping is a ROW-level contract, not a source-set one.** `sourcesForKind(claude)` returning `{SourceBuiltin}` isn't enough — the `builtin` source curates across providers (gemini, gpt, grok sit beside anthropic ids), so a claude completion could still offer ids a claude child can never run. `filterRowsForKind` applies the provider filter at the ROW layer; test the rows a filter produces, not the sets it selects.
- **Anthropic ids have two spellings, and the catalog only knows the dotted one.** OpenRouter says `anthropic/claude-opus-5.5`; the native sender and the claude kind's rows say `anthropic/claude-opus-5-5`. `routing.nativeAnthropicID` is the one predicate for "the native sender can run this entry" (drops `~` aliases, `:batch` twins — which share their base's `created` stamp — and `-fast`), surfaced as `CatalogRow.AnthropicID`. `ListModelRows` uses it to extend the builtin spine with every catalog Anthropic model and to key facts by the dashed id; `knownModels` is only a cold-cache warm-start. Pinned by `TestListModelRowsClaudeKindFollowsCatalog`.
- **Every OpenRouter sender must carry `x-session-id`, and the only correct way is `llm.SenderFor`/`SenderForKey` — never hand-roll an `anthropic.NewClient` pointed at OpenRouter.** Without it, OpenRouter's sticky routing hashes only the first system+user pair, so a conversation's static prefix stays warm while everything appended after it can land on a cold replica — indistinguishable from "this model doesn't cache" by token counts alone. `SenderForKey` wraps the sender in `sessionIDTransport`, reading the id from ctx via `llm.WithSessionID`.
- **`kind = "openai"` is implemented as a translation layer at the sender boundary only (`pkg/llm/openai_sender.go`), never per-vendor.** `base_url` is required (no canonical OpenAI-compatible default — `SenderForKey` rejects an empty one); an empty key sends no `Authorization` header at all (local keyless servers like Ollama); the capture transport wraps `rt` unconditionally, so raw-trace capture sees this kind's traffic. Both `New` and `NewStreaming` share one request builder (`buildOpenAIChatRequest`) and one five-way finish_reason table — add a field or remap a reason in both through those, not in the paths. The SDK's `Message.Accumulate` applies every delta to the LAST block regardless of `Index`, so the streaming decoder keeps exactly ONE block open (close-then-reopen on source switch; ids/names for a reopened tool block are not re-emitted). Trim-and-retry is Anthropic-API-specific: an oversized prompt fails the turn permanently on this kind (`isPromptTooLarge` needs `RawJSON()` and an Anthropic-specific substring).
