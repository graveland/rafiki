# The executor plane

Confinement is the point of this whole subsystem: workspace tools must never
silently run in the daemon's own process, and a child must never reach an
executor its parent couldn't. Same discipline as CLAUDE.md applies here —
write the rule and where it's enforced, not the incident story; prune an
entry the same edit that makes it stale.

- **A `Materializer` may decline by returning `(nil, nil)`; `MaterializeAll` then omits it from the Registry.** This is how `SkillBlueprint` keeps a useless `skill` tool out of `tools[]` with zero skills discovered. `Registry.Register` does NOT guard against nil and panics inside `BuildDef` on a nil-interface deref — any caller materializing a blueprint by hand must nil-check first. The largest instance: the whole workspace tier (`read`/`write`/`edit`/`glob`/`grep`/`ls`/`bash`/`lsp_*`) is omitted when `opts.Executor == nil` (see `blueprint.go`'s comment on that check for why it never falls back to in-process).
- **A tool's `ToolResult` is flattened to a `string` inside `Registry.Register`'s closure, not inside `Registry.Execute`.** Anything changing how results become model-visible content (content blocks, images, per-tool budgets) belongs in the `Register` closure. A non-text result would need `Registry.Execute`, `agentloop.ToolSet.Execute`, and `anthropic.NewToolResultBlock` to all change together.
- **Custom auth headers survive cross-host redirects; only `Authorization`/`WWW-Authenticate`/`Cookie` are stripped.** Outbound clients in `pkg/fundi/tools` go through `newGuardedClient` (dialer `Control` hook, survives DNS rebinding and redirects) and, for credentialed calls, `newBraveClient`, which deletes the credential on a host change. Any new outbound client belongs on this path.
- **`rtk` has no distinct exit code for "I refuse to run this"** — refusals and genuine failures both exit nonzero. The discriminator is that rtk prefixes its OWN diagnostics with `rtk: ` on stderr; `rtkRefused` (`pkg/fundi/tools/bash.go`) keys on that to re-run under plain bash, biased toward NOT falling back (a false positive re-runs a failing command twice).
- **Quoting rules differ between `'` and `"`, and the rtk rewrite guard must honour that.** Single quotes make every shell metacharacter inert; double quotes still expand `$`, backtick, `$()`, and honour `\`. `hasShellChaining` refuses those inside `"…"` while leaving `;`/`|`/`&`/`<`/`>` inert there — treating both quote kinds alike let `git commit -m "release $VERSION"` reach rtk's argv and commit the literal string.
- **Claude Code's skills-dir plugin contract: a plugin's skills load ONLY from `<plugin>/skills/<name>/SKILL.md`** — skill directories at the plugin root are invisible regardless of `.claude-plugin/plugin.json`. `pkg/executor/skill_sync.go`'s renderer writes exactly this shape (pinned by `TestSyncWritesASkillsDirPlugin`). A bare `skills/<name>/SKILL.md` at the TOP level of the skills dir is also adopted (the flat, pre-plugin layout). Claude Code keeps its own `<skills-dir>/manifest.json` for sync-owned entries: absent is fine (adopt-all), present-and-malformed is fail-closed for the whole dir. Never prefix names to "fix" the layout — Claude Code derives `rafiki:<name>` from directory structure and the fundi renderer must keep agreeing.
- **A pymodule syncs to `<cache>/pymodules/<name>/<name>.py` and is consumed in place, never copied — including the entry script, which is itself a pymodule.** `pymodule_run`'s `script` is a saved module name (validated with `pymodules.ValidName`, never a path), executed as `<name>/<name>.py` out of the synced cache. The process cwd is the calling agent's workspace, or the call's own `cwd` — resolved by `resolveToolPath` like every file-tool path; the run shares `bash`'s subprocess plumbing, so an explicit `cwd` is exactly the `cd <dir> && python …` half, with `sys.path[0]` staying the script's cache dir. Bytecode from imports lands inside the modules' own cache dirs and is left there — the prune sweeps at ROOT level only (`os.RemoveAll` for absent module dirs, also how a legacy flat `<name>.py` migrates; `os.Remove` for symlinks, never followed out), so per-dir `__pycache__` survives between runs. Enforced in `pkg/executor/pymodule_sync.go` and `pkg/fundi/tools/pymodule_run.go`; pinned by `TestSyncPyModulesPrunesSymlinkWithoutFollowing`, `TestPymoduleRunExecutesCacheCopy`, and `TestPymoduleRunRunsInAgentWorkspace`.
- **A pymodule declares dependencies with a `# pymodule-requirements:` marker; the executor builds a per-module `.venv`; `pymodule_run` composes it.** The marker must be the whole trimmed line; following contiguous `# `-lines are requirements.txt-style pins (`pkg/pymodules/requirements.go`, `ParseRequirements`/`RequirementsHash`). The executor's sync builds `<dir>/.venv` hash-gated (`.rafiki-requirements-hash`, no trailing newline), staged in `.rafiki-venv-staging-*` then remove-then-renamed; `uv` is REQUIRED (no pip fallback) and only needed by modules that declare requirements — `RAFIKI_PYMODULE_UV` overrides it and on the daemon also selects the advisory ruff lint. `SyncPyModulesResponse.VenvResults` reports one entry per corpus module: `ready` is true for no-requirements AND successful builds, false only for a declared-and-failed build. `pymodule_run` then: runs the script under its own `.venv/bin/python3` when present, puts every venv-having entry's `site-packages` on `PYTHONPATH` (script contributes site-packages only — its code dir is `sys.path[0]`; a pure PYTHONPATH union, no reconciliation), and REFUSES a run when requirements are declared but the venv is missing — staging DIRECTORY means "build in progress" (retryable), anything else "dependencies not ready". Gate: `TestBuildVenv*` in `pkg/executor`, `TestPymoduleRunNotReady*`/`TestPymoduleRunScriptVenv*` in `pkg/fundi/tools`; wire contract in `docs/reference/executor-protocol.md`.
- **Git-sourced pymodules live in a SIBLING cache root, `<cache>/pymodule-repos/<source>`, one checkout + one shared venv per registered source — never inside `<cache>/pymodules`.** The daemon holds `(owner, name, url, ref)` and fans `SyncPyModuleGitSource` out to eligible executors (`Describe` reports `pymodule_git_sync`); each executor clones (or `fetch origin <ref>` + `git reset --hard FETCH_HEAD` + `git clean -fdx` on refresh) into that root, discovers `scripts/*.py` plus top-level `__init__.py` dirs, and builds `<root>/.venv` via `uv sync` against the checkout's OWN manifest (pyproject.toml required — a requirements.txt-only repo reports venv-not-ready, no build). The handler refuses a leading-dash `url`/`ref` before any subprocess — git would otherwise parse a crafted ref as a fetch option (`--upload-pack=…` executes locally). On the run side, `pymodule_run`'s required `repo` argument selects the source (`"local"` = the blob corpus above): script at `scripts/<script>.py`, the checkout ROOT always joins `PYTHONPATH` first so intra-repo imports resolve, `.venv/bin/python3` as interpreter when present, missing venv = visible import-time failure, never a refusal. Enforced in `pkg/executor/gitpymodule_sync.go` + `pkg/fundi/tools/pymodule_run.go`; pinned by `TestSyncPyModuleGitSource*` and `TestPymoduleRunRepo*`; wire contract in `docs/reference/executor-protocol.md`.
- **`runSubprocess` REPLACES the child env when env is non-nil — hand-fold anything the child needs.** (`pkg/fundi/tools/bash.go`, `cmd.Env = env`.) `pymodule_run` folds the parent `PYTHONPATH` into the single var it passes, so a script WITH modules (or with its own venv), and every git-sourced script, runs with PATH/HOME/TMPDIR stripped — for the venv'd-no-modules and git cases that's a parked design question (a future `os.Environ()`-based env is the candidate fix), not an accident. Test corollary: a fake interpreter script that execs real python must bake the ABSOLUTE path (`exec <LookPath'd python3> "$@"`) — a bare `python3` won't resolve with PATH gone.
- **`Release` ends only its OWN workspace's jobs.** `releaseWorkspace(id)` signals the process GROUP, matching `kill()`, so a background `npm run dev` doesn't strand its tree. It is also the only thing that ends output retention, since there is no timer.
- **A tool proxied to the executor's ROOT registry must not let "your working directory" mean that root.** An `Execute` without a workspace id serves the executor's own registry, whose `Cwd` is the executor's process root (`toolOptsFor`) — and a claude-kind child, the whole audience of the MCP pymodule surface, has no workspace id to route with (`controller.go`: claude has no workspace concept). So `mcpPyModuleRunExecutor.bindCwd` (`cmd/rafikid/mcp_pymodule_run.go`) rewrites the input's `cwd` against the calling child's stored cwd BEFORE the bytes leave the daemon — absent/relative resolve there, absolute and `~` pass through — while a workspace-carrying caller additionally gets its `rafiki/workspace` label stamped as `WorkspaceId`. Pinned by `TestMCPPyModuleRunExecutorBindsCwdToTheCaller`. Without it a relative `cwd` resolved against the executor's checkout tree: loud when the name didn't exist there, silently wrong-tree when it did.
- **One classification, three derived lists, and a tool you add to none of them fails a test.** `tierByTool` (`pkg/fundi/tools/executor_routing.go`) is the single source: every tool is `TierDaemon` or `TierWorkspace` — binary by construction, enforced by `TestEveryDeclaredTierIsCarried`/`TestEveryBlueprintHasATier`. `WorkspaceTools()` (17, needs an executor) minus the 3 background-job verbs (parent-side RPCs, never reach the executor) = `ExecutorLocalTools()` (14, what `executor.NewServer` builds with `MaterializeOnly`); adding the job verbs back = `RoutedToExecutor()`. `TierDaemon` (`task_*`, `web*`, `agent_*`, `executor_annotate`, MCP, `skill`) stays in the daemon, keeping credentials above the confinement boundary. `MaterializeAll` (daemon path) omits the whole workspace tier when `opts.Executor == nil` and intersects the routed set with the executor's `Describe`; building the executor's own registry with `MaterializeAll` instead of `MaterializeOnly` panics (`ToolOpts.Tasks` is nil there).
- **`tools[]` is IMMUTABLE for a child's lifetime.** Tool definitions sit inside the prompt-cache breakpoint, so any mutation invalidates the whole cache. Losing a capability never needs a `tools[]` change — the tool stays declared and its calls return `is_error`, since a model can only emit `tool_use` for a declared tool. Wanting to add a tool mid-conversation reopens a decision recorded in `docs/reference/executor-protocol.md`.
- **`tools.AgentSpawner` is bound to ONE child at construction and takes no caller identity in any method.** Easy to undo by "simplifying" into a shared value with a `selfID` parameter — don't: fundi children run in-process, so a self id passed as a parameter is one refactor from being a tool argument an LLM can be prompt-injected into naming as a sibling. `newControllerSpawner` is built per-child from `agentRuntimeOptions`, where the daemon-stamped `childID` is already in hand.
- **The MCP agent-control surface (`/mcp`) is mounted INSIDE the proxy face via `pkg/server.Handler`'s `MCPPath`/`MCP`, and its server is built PER REQUEST from `server.IdentityFromContext`.** A `mux.Handle("/mcp", …)` in main.go compiles and silently shadows the face's auth (ServeMux prefers the longer pattern). A single shared MCP server would put a user id back into an `AgentSpawner` method parameter — one refactor from being a prompt-injectable tool argument; `NewStreamableHTTPHandler`'s `getServer func(*http.Request) *Server` exists to make per-caller binding possible instead. Session-identity binding (`mcp_face.go`'s `Routes`/`sessionOwnedBy`) is load-bearing because the SDK's own hijack guard is inert on this mount — without the wrap, any authenticated caller presenting another caller's `Mcp-Session-Id` executes that caller's bound tool set. Only a `ProvenanceUser` identity or a per-child token (`ProvenanceChildToken`) passes the agent-control gates — a non-empty-UserID check must never stand in for provenance, since a child-attributed identity also carries one. Settlement notifications ride `ServerSession.Log`, which silently drops every message until the client sends `logging/setLevel` — `agent_list`'s status field is the reliable signal, not the push.
- **The executor DIALS rafikid and then SERVES HTTP/2 on what it dialled; rafikid accepts and is the HTTP client.** (`pkg/execpool/transport.go`) `DialTLSContext` is the hook even with no TLS (no `DialContext` on `http2.Transport`); a second dial request is the reconnect signal, not an error; both sides must set `NextProtos: []string{"h2"}`; the hello frame must be read byte-at-a-time or a buffered reader leaves `http2.Transport` starting mid-frame — the OPPOSITE of the control listener, where the handshake reader must be reused.
- **`executors.Store.Delete` is a real hard delete, unlike `users`** — the only FK into `conversations.executors` is `ON DELETE SET NULL`. `pool.go`'s `refreshRow` distinguishes `errors.Is(err, executors.ErrNotFound)` (terminal — evict now) from any other `Get` error (transient — keep the last known row); getting this backwards either evicts a live connection over a DB blip or lets a deleted-but-connected executor keep serving forever.
- **`conversations.executors` is authoritative on every connection; the credential proves only binding to a row.** Nothing that gates access may be cached from enrollment time, and nothing self-reported by the executor may reach the `labels` column (`self_reported` is a separate column). This is what makes relabelling and revocation row updates need no reissue, no restart, and no access to the machine.
- **Executor narrowing is runtime intersection, never a subset proof.** Compute the parent's effective executor set, evaluate the child's selector independently, intersect. Proving a child's selector implies its parent's is decidable for equality matches and a logic puzzle the moment `notin` appears — and it fails OPEN, the wrong direction for a confidentiality boundary.
- **A child's executor set is its PARENT'S set intersected with its own selector — never `Live()` filtered by the child's selector alone.** `effectiveExecutorSet` walks the lineage root-first so an ancestor's constraint can never be widened by a descendant's, and a malformed selector — on either side — EXCLUDES rather than admits.
- **`Executor.Admits` is the executor-side half of selection and is easy to store and never evaluate.** An agent-side selector alone is permissive by default (it says what the agent wants, not what the executor will take). Both halves are evaluated in `effectiveExecutorSet` — a malformed admission selector EXCLUDES, never admits, so an operator typo can't silently open a machine to every child.
- **`Pool.mu` is a `sync.RWMutex` and is not reentrant — never block while holding it.** A goroutine blocking holding `Pool.mu` wedges `Live()`, `ClientFor()`, and every subsequent accept — one unwell executor takes the whole executor plane down. `onHealthFailure` deletes from the live set under the lock, then calls `Park` outside it.
- **The executor row is the ONLY authority on what an executor is — never trust the self-report.** `Describe`/`ProvisionResponse` deliberately leave `isolation`/`workspace_mode` EMPTY; everything downstream reads `executors.Executor` (the row the operator wrote at mint time) instead — `workspaceInfoFromRow`, the `rafiki/workspace-mode` label, `narrowByWorkspaceMode`. Trusting the self-report has already failed twice: `BuildSystemPrompt` silently dropped the sandboxed-worker warning when it read `resp.Isolation`, and a hardcoded `"pinned"` workspace-mode label made the reschedule path dead code — both invisible because the tests had been updated to match the self-report. Transient executors (`rafiki create`/`attach`, no DB row) are the explicit exception: their access-gating facts are written by the daemon from the authenticated control connection. General rule: every access-gating fact is written by the daemon from something it verified. `refreshRow` must skip transient executors, or `store.Get`'s `ErrNotFound` (row never existed) reads as "deleted, evict now" and kills a healthy executor on its first health tick.
- **An unknown workspace mode is PINNED, never ephemeral** (`workspaceModeOrPinned`). Pinned means an executor loss fails the child where it stood; ephemeral means the daemon reschedules it. Defaulting an absent value to ephemeral reschedules children onto machines no operator ever marked interchangeable.
- **Native executors have NO path scoping, deliberately** — `--root` is a working directory, not a sandbox. The file tools could enforce a scope in userspace but `bash` could not, and a scope that evaporates on the first shell command is worse than none. For containers the mounts are the grant and the kernel enforces them; the row's `roots` DESCRIBES that view for humans and selectors but enforces nothing, which is why the workspace block prints roots bare — an invented "read-write" label would be a claim the daemon can't back.
- **The workspace block belongs in the system prompt's ENVIRONMENT section, never in `defaultBasePrompt`.** It varies between children, and anything that varies must follow the cacheable sections — rafiki's prompt-cache breakpoint sits over the tools+system prefix. A native, unsandboxed agent gets no block at all.
- **A confinement guard is only as good as the paths that reach it — look for the bypass, not the flaw.** Two criticals shipped this way: an empty executor selector let `resolveExecutor` return `(nil, nil)` and run the child's tools in the daemon process (closed by requiring workspace tools to have an executor, never falling back to daemon-local); and a container grant was enforced for `bash` while five other tools went to a host-scoped registry that never entered the container. When you add a guard, enumerate every path to the guarded resource and assert the guard sits on all of them.
- **rafiki does not launch containers, and an executor declares nothing about itself.** A container running `rafiki executor serve` IS a container executor; every fact that gates access (`labels`, `isolation`, `workspace_mode`, `roots`, `admits`) comes from `conversations.executors`, set at token-mint time by the operator. There is no `--isolation`/`--workspace-mode`/`--image`, and **container detection must never be added**: sniffing `/proc/1/cgroup` would be the executor asserting a fact that gates it, which `SelfReported` already forbids.
- **launchd seeds `SSH_AUTH_SOCK` into every LaunchAgent, which makes `executor.env`'s captured value for it inert** — that's what `executor-overrides.env` exists to beat. `rafiki executor serve` applies `executor.env` (fill-gaps) then `executor-overrides.env` (every variable set UNCONDITIONALLY, `RAFIKI_EXECUTOR_OVERRIDES_FILE`). Install never writes the overrides file — hand-curating the vars automated capture gets wrong is the whole point.
- **Background job output is retained by BYTES until the workspace is released, never by a timer.** A wall-clock window is meaningless for an async agent whose turn can end and resume hours later. A byte budget (`--job-output-budget-mb`) evicts the oldest FINISHED job first; a running job is never evictable since its output is a live stream.
- **Background jobs notify on exit, the way subagent settlements do — the tool descriptions promise it, so the watcher is not optional.** `cmd/rafikid/jobwatch.go` polls every job through `boundExecutor.peekJob` (reads the CURRENT binding, never `recover` — a re-provisioned workspace can't hold the job) and pushes the exit into the child's eventbuf. A watch ends only on a definitive answer (exited, Found=false, child gone) — an RPC error is transient and must not end the watch, or one executor blip strands every notification. The liveness check runs BEFORE the poll, not only after a successful one — that ordering is the whole reason a closed child's watch ever ends, since a closed child's `boundExecutor` is gone and every poll fails first. Watches are in-memory and not re-armed on recovery, so a job running across a daemon restart notifies nothing.
- **`tools.RTKMode("")` is NOT `RTKOff`** — `rtkRewrite` short-circuits only on the literal `"off"`, so a zero value behaves like `auto`. `Options.RTK` is explicit now and `toolOptsFor` makes the Options→ToolOpts mapping testable, since an unset field there doesn't fail, it silently takes a zero value. Background bash is never rewritten regardless — the refusal fallback needs an exit to inspect and a long-running job has none.
- **`Pool.live` must be mutated on connection IDENTITY, never on executor ID alone.** An executor restart installs a new `liveConn` under the same ID before the old connection's health loop notices (up to a full tick), so both are live at once. A delete keyed by ID lets the stale loop evict its own replacement. Compare the pointer before deleting (`removeLive`), close any `liveConn` you displace (`installLive`), and keep teardown idempotent — it arrives from two directions.
- **An auth failure has two meanings and they are not interchangeable, for executors too.** "Invalid credential" (stop) vs. "could not check it" (retry) — an executor that treats the second as the first takes itself permanently out of service over a DB blip, which across a fleet reconnecting together is the whole fleet. `ExecutorHelloResponse.Retryable` carries the distinction; `executors.IsTerminalAuthError` fails toward retry. The sentinels live in `pkg/executors`, not `pkg/executorsdb`, because the executor links `pkg/execpool` and must not link pgx.
- **`NoteBinding` writes the CHILDSTORE; `c.wsLabels` is only a pre-spawn bridge.** `handleChildExit` releases a workspace by `snap.Labels`, so a binding that stops at `wsLabels` is invisible to it — the child leaks its live workspace. The map is consumed exactly once, under `wsLabelsMu`; an unlocked read there is a fatal concurrent map access now that tool goroutines write it.
- **`ErrStreamBroken` means MAYBE RAN, and is the only liveness error that does.** Every other sentinel is pre-dispatch. Re-provisioning does not give a fresh filesystem — same `--root`, mounts unset — so a broken stream retries for idempotent verbs only. A new tool defaults to non-idempotent by omission from `idempotentTools`, the safe direction.
- **`boundExecutor` caches its client and calls it directly, so `Pool.ClientFor`'s typed departure answers (`ErrParked`/`ErrExecutorLost`/`ErrDraining`) never reach it after the first bind — only `ErrDialFailed` (from a failed `c.inner.Execute()`, before any stream) and `ErrRedialed` (the dial hook's second-connection refusal) do.** A dead HTTP/2 connection surfacing any OTHER shape of error at that pre-stream point (a bare `write: broken pipe`, `use of closed network connection`) used to carry no sentinel `isLivenessFailure` recognized, so `retryable` refused every non-idempotent tool (bash/write/edit — most real tool calls) and `recover` never ran: the child stayed bound to the same dead client forever, healed only by restarting rafikid and rebuilding every binding from scratch. `workspaceClient`/`executorClient`'s `Execute`/`StartJob` now wrap that pre-stream error with `ErrDialFailed` unconditionally — connect-go's `CallServerStream` only returns a client-side error there for a failure that never reached the server (a response the server already sent comes back as `io.EOF` and is left for `stream.Err()`/`ErrStreamBroken` instead), so it is always safe to retry any tool. Pinned by `TestExecuteRecoversFromADeadConnectionOnASideEffectingTool` (`cmd/rafikid`) and `TestErrDialFailedIsDistinctFromStreamBroken` (`pkg/execpool`).
- **A pinned child never changes machines, on either path.** `HandleExecutorLost` fails it after the park timeout and `boundExecutor.recover` refuses to re-select for it; re-provisioning on the SAME executor is allowed for both modes, because the executor's in-memory workspace registry loses every id on restart while the machine is fine.
- **The executor's name is `labels["machine"]`, written by the operator — there is no derived machine id.** Optional (a fleet executor selected by `env=prod` needs none) and unique per owner. Never a hostname fallback — on darwin a hostname changes with the active network interface.
- **A top-level spawn whose selector matches nothing is REFUSED; a parented spawn starts UNBOUND.** `agentRuntimeOptions` gates on `req.ParentChildID` — a human-operated spawn gets `explainNoMatch`'s diagnostic, an agent-spawned child waits. An unbound child carries `rafiki/executor-state=unbound` in its labels, removed by `NoteBinding` on the first successful bind.
- **`boundExecutor` is the only client for executor-bound work.** The old `resolveExecutor`/`selectExecutor` path is deleted; `chooseExecutor` is the single selection entry point.
- **A transient executor must never touch the store** — its id is `sess-<ULID>` against a UUID column, and any `TouchSeen`/`reattach`/`refreshRow` call is a silent round trip the store rejects. `Evict` records a tombstone so an executor still in its join window is stopped; `installTransient` checks it before installing.
- **One session executor per control connection.** `ExecutorSession` detects a previous session on the same connection and releases it (revokes the ticket, evicts the executor) before installing the new one.
- **A routed tool must return an ERROR, never the error's text as a successful result.** `agentloop` computes `is_error` as `err != nil`, so a tool that swallows a failure into `NewErrorResult(err), nil` reports SUCCESS carrying the diagnostic as output — both to the renderer (a ✓ for work that never finished) and to the MODEL, which is told its call succeeded. `executorProxy.Execute` and `jobs.go`'s background-job tools both had this bug; agentloop substitutes `"Error executing tool: %v"` when a failing tool yields no text, so nothing is lost by returning the error properly. `webfetch`/`websearch` still swallow deliberately — a daemon-tier tool's network/input failure is reasonably retryable by the model, a different question from infrastructure that never ran at all.
- **`ProvisionRequest.workdir` is honored per workspace, and it is what makes `agent_spawn`'s `cwd` real for executor-bound children.** The executor validates the workdir exists (existence-only, never under-root containment — a native executor has no path scoping and sibling git worktrees must keep working) before materializing a per-workspace tool registry with `Cwd: workdir`. Refusal is loud (`CodeInvalidArgument`), because silently starting in the root while the prompt names another directory is the split-brain that caused workers to commit to `main`.
- **`agent_spawn`'s `workspace: ephemeral|pinned` is a RESCHEDULABILITY choice, never an isolation one.** One executor serves one root for every workspace on it; the mode only narrows which executor rows may serve the child and what happens on executor loss. Isolation is git worktrees plus `cwd` — any description claiming a "fresh, isolated checkout" is drift.
- **An `agent_spawn`/`ctrl_spawn` executor grant is normalized at spawn, so both a bare-word selector and an omitted one resolve consistently.** (1) A bare word (`executor: "greyshift"`) is promoted to `ExecutorRef` and resolved by machine name/id against the confinement-narrowed set. (2) A ref-only grant is persisted as `machine=<label>` on the stored selector, or lineage narrowing and resume would lose the pin. (3) `agentRuntimeOptions` keys the `boundExecutor` off `c.execPool != nil`, never off the selector — an empty selector means the child's EFFECTIVE SET, and a pool-less daemon is the only case that still spawns toolless children; a top-level spawn with an empty selector and zero live executors is REFUSED, not started toolless. **A DB-backed daemon with no `RAFIKI_CONTROL_LISTEN` defaults the pool ON**, so any test boot helper spawning plain children must set `RAFIKI_EXECUTORS_ENABLED=0` or every spawn dies with `no executor satisfies ""`.
- **Script hosting is routed, not forked everywhere: `scriptExecutorRouted` (`cmd/rafikid/script_runtime.go`) sends a `kind: script` child to daraja on an executor when the pool is configured AND a live executor advertises `--launch script`; otherwise the LOCAL runner stays the fallback.** The routing predicate is the same one `checkKindNarrowing` consults (`checkKindNarrowing(st, req, claudeExecutorRouted, scriptExecutorRouted)`), so a confined parent's script child is admitted exactly when it launches on the pool and refused when the fallback would fork on the daemon's host — a selection failure while the pool DOES advertise the kind propagates (never silently falls back). The executor-hosted launch (`pkg/executor/script_launch.go` + `AdminServer.Launch`'s script branch): the executor resolves `ScriptParams` against its OWN synced cache at launch time (blob corpus with venvs, git checkouts with the shared venv — `pymodule_run`'s resolution, helpers exported from `pkg/fundi/tools`), passes the interpreter as `--binary` and the resolved argv positionally, and puts `PYTHONPATH`/the forwarded env in the daraja process's environment. `--launch script` implies `--pymodules-sync` and `--pymodule-git-sync` (explicit false wins); the executor needs an `owner` label or the corpus never reaches it. The child secret rides `ScriptParams.child_secret` → env `RAFIKI_CHILD_SECRET` (never argv, in `rafikiCredentialEnvNames`' scrub list) and daraja serves `pkg/childsock` against the daemon's face with the executor's own pin posture (`--pin-cert`/`--server-name` ride every launch). Respawn is OFF for scripts (`Host.respawn` gives up for non-claude kinds) and `RelayResponse` gained a `stderr` arm (a script's settle tail is its stderr; claude's stays discarded).
- **The local script runner (`cmd/rafikid/script_runtime.go`, now `localScriptRunner`) wraps `child.NewProcessRunner` — it does not reimplement subprocess semantics.** Own process group, process-group SIGTERM/SIGKILL, and the Wait contract come from the shared runner; the wrapper only adds materialization (pymodule store → `script-host/<childID>/`, one dir per name, script dir off PYTHONPATH because it is `sys.path[0]`), the stripped environment (`scriptChildEnv`: full daemon env minus `RAFIKI_*`/`ANTHROPIC_*`/`OPENROUTER_*` — the one list lives in `pkg/child.ScriptEnvStripPrefixes`, applied on the daemon, the launch payload, and daraja alike — forwarded `req.Env` stripped by the same rule, computed `PYTHONPATH`, then `RAFIKI_CHILD_CONNECT`), and the per-child socket's lifecycle (closed and unlinked in `Wait`). Git-sourced repos and requirements-without-venv are refused with the executor-hosting pointer.
- **A daraja-hosted script's `Exited` is defended at BOTH ends of the relay — losing either one strands the child row as `streaming` forever.** Daemon side (`pkg/darajapool/relay.go`): the pool's replay belt holds events broadcast while no Watch subscriber was attached (cap 256/child, drop-oldest so the terminal event survives) and serves them to the FIRST subscriber — or, with no live connection, hands the whole belt over once via `Watch` (channel closes after) — because the dangerous window is exactly where the holder dies (daraja exits with a fast script) and a holder-owned buffer would die with it. Belt consumption is PUMP-ONLY: the DarajaWatch admin RPC goes through `Pool.WatchLive`, which never serves the belt — an admin watch landing inside the pump's ≤500ms re-Watch backoff (holder dead, belt non-empty) would otherwise drain it and re-strand the child (pinned by `TestBeltIsPumpOnlyAdminWatchGetsLiveOnly`, `pkg/darajapool/relay_replay_test.go`); the belt's safety is the ordering + one-shot argument, never a claim about which frames it can hold (a disconnect gap can belt post-prompt frames). The belt is deliberately one-shot and kind-UNaware: an event is either live-delivered or belted, never both, so claude cannot see a frame twice, and the pump's `TakeResetPending` ordering survives (same ordered stream). Lock order is always `holder.mu` → `p.mu` — `RelayFor` must stop a stale holder OUTSIDE `p.mu`, or a subscriber-less broadcast deadlocks against it. daraja side (`cmd/rafiki/cmd_daraja.go`, `runDarajaConnectLoop`): the host-gave-up path (a script's normal end) does NOT exit immediately — it cancels the reconnect loop and waits (≤`darajaRelayTailGrace`) for the daemon to close the connection, because the daemon only closes after receiving the relay stream's final frames; killing the process at `host.Done()` raced the flush and ate the `Exited` under load. Pinned by `TestPoolReplayBelt*` + `TestScriptExitBeforeTheFirstSubscribeStillReachesTheRunner` (`pkg/darajapool/relay_replay_test.go`).
- **`pkg/childsock` must never run a umask dance — `syscall.Umask` is process-global.** serveConnectUDS gets away with set-bind-restore because it runs once at boot; a per-spawn dance racing any concurrent file creation clamps THAT creation (and a botched restore clamps every later one) to 0600. The per-child socket binds plain and chmods 0600 immediately after; the 0700 per-child directory is the real access boundary. The socket is a credential-injecting proxy (strips inbound `Authorization`/`X-Rafiki-*`, injects the child secret) — never proxy it at the raw Connect handler, which would fail OPEN: the token middleware that resolves the child identity lives on the face's mux, not on the Connect route.

## Known pre-existing issues — each needs its own task

Real, deliberately unfixed (out of scope for the work that found them), and easy to misread as new breakage. Fix none of them in passing; file the task instead.

- **Executor SIGTERM strands a live script child** — `cmd/rafiki/cmd_daraja.go`'s signal branch in `runDarajaConnectLoop` discards `host.Shutdown(0)`'s exit info and emits no `Exited` on the relay, so a script alive at executor shutdown stays `streaming` forever; the belt can't help (nothing was ever broadcast).
- **`handleConn`'s double `removeLive` makes `OnDisconnect` dead code on the real path** — `pkg/darajapool/pool.go` removes the connection unconditionally and then re-asks (always false), so a genuine daraja disconnect never fires the callback that marks the child unreachable; only `Evict`/displacement do.
- **Kill-path Shutdown-response flush race** — `pkg/darajapool/runner.go`'s `Runner.shutdown` reports the documented `-1` sentinel on any `Shutdown` RPC error, and a response flush racing connection teardown during kill surfaces as exactly that error, so a kill may report exit code -1 instead of the real one.
- **`TestRefusedDialSurfacesAuthInvalidOnFirstRequest` flakes ~1-in-3 under parallel load** (`cmd/rafiki/cmd_user_token_test.go`) — a broken-pipe error can win the race against the auth-error read on the refused dial; passes in isolation. Pre-existing, unrelated to script children.
