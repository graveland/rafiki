# Making Claude Code itself behave

This is specifically about the Claude Code *binary's* own quirks and gates —
its stream watchdog, its OAuth decision, its tool-search behavior, its
argv/env launch contract — as opposed to how rafiki represents a Claude Code
session in its own data model (see daemon-state-and-recovery for thread
reconstruction). Same discipline as CLAUDE.md: rule + where it's enforced,
no incident narration, prune when stale.

- **A `reason="client canceled"` abort with a small `last_byte_ago` is Claude Code's stream idle watchdog, not a proxy stall.** Claude Code re-arms a 300s idle watchdog on every event its consume loop yields; SSE pings only count as activity when the base URL host is exactly `api.anthropic.com` (`_CLAUDE_CODE_ASSUME_FIRST_PARTY_BASE_URL=1` overrides this). Through a proxy on a custom host, a thinking phase with >300s between content events dies with "Response stalled mid-stream" even though bytes flowed. `pkg/proxyenv.Defaults` sets the override for rafiki-spawned claude children; hand-configured clients need it themselves (README). Rule out a real stall first — check for `ResponseWriter is not an http.Flusher` / `h2 transport configure failed` / `llm turn truncated` in the log; if absent and `last_byte_ago` is small, this is the diagnosis.
- **`_CLAUDE_CODE_ASSUME_FIRST_PARTY_BASE_URL=1` also silently re-enables deferred tool search, which 400s every non-Anthropic model.** Claude Code gates the byte watchdog and tool search on the same predicate, so fixing the watchdog reopens this: a session on an OpenRouter-routed model dies on its first turn with `400 Deferred custom tools are only supported on Anthropic models`. `proxyenv.ClaudeEnv` sets `ENABLE_TOOL_SEARCH=false` whenever the model isn't an Anthropic id; hand-configured clients need the same for a non-Anthropic model.
- **`proxyenv.ClaudeEnv` is the only launch-decision entry point** — `(env []string, Values)`, where `Values.MCPConfig` is bare inline JSON and `claudeargv.Build` prefixes it with `--mcp-config=` (never hand it a pre-rendered element, or you get `--mcp-config=--mcp-config={...}`; pinned by `TestBuildClaudeArgvCarriesMCPConfig`). The MCP config points at `<URL>/mcp` with `Authorization: Bearer ${RAFIKI_MCP_TOKEN}` as a placeholder Claude Code expands at connect time — never inline (argv is world-readable via `ps`). The `/mcp` path literal exists in both `pkg/proxyenv` (`mcpPath`) and `cmd/rafikid/mcp_face.go` (`mcpFacePath`) — grep the other side before changing either. `TestClaudeArgvIdenticalAcrossPaths` pins both spawn paths (interactive, daraja) to byte-identical argv.
- **Claude Code's OAuth gate does NOT look at `ANTHROPIC_BASE_URL` — only `ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_API_KEY` suppress the subscription credential.** A plain-HTTP custom base URL with no `ANTHROPIC_AUTH_TOKEN` still receives the OAuth bearer token plus the `oauth-2025-04-20` beta header, and Anthropic accepts it forwarded from an ordinary Go client. This is what `rafiki claude --passthrough-auth` rests on. The credential arrives in `Authorization`, never `x-api-key`; dropping `oauth-2025-04-20` from `anthropic-beta` on the way upstream turns a working request into a 401, so the header forward in `buildAndDo` is load-bearing.
- **The proxy's Anthropic rate-limit capture (`MessagesProxy.captureQuota`) runs BEFORE the 4xx/5xx branch in `streamAndCapture`, on every response shape** — deliberately, since a 429 is exactly the response most worth capturing headers off. It runs in a detached goroutine, not inline, to avoid adding a DB round trip to time-to-first-byte on every passthrough turn. Any new early-return branch added above this call silently loses capture coverage for that response shape.
- **A claude child's turn that dies of a 429 is detected at the PROXY, not from the child's stdout.** `MessagesProxy`'s `RateLimitObserver` (`pkg/server/proxy.go`) reports main-thread 429s and clean completions to the Controller, which schedules an auto-resume for the limit's reset (`cmd/rafikid/ratelimit_resume.go`, capped at 3 consecutive attempts). The child's own `rate_limit_event` frame (fixture `pkg/child/testdata/claude/turn_with_tool.jsonl`) is NOT the trigger — it fires with `status:"allowed"` on healthy turns too and the blocked-state spelling has never been observed live; the proxy's 429 is upstream truth. Observer calls are gated on `cr.on` AND `!cr.isSubagent` (a Task subagent's 429 must not schedule its parent's resume) AND a non-empty `X-Rafiki-Session`, which for daemon-spawned children IS the child id — an interactive `rafiki claude` session's UUID resolves to no child and is ignored, so the controller re-checks kind (claude) and `!Native` rather than trusting the header alone. The `anthropic-ratelimit-unified-{5h,7d}-reset` headers outrank `Retry-After`; the zero time means unknown and falls to a backoff ladder. An operator's Kill and the daemon's shutdown drop the watch at their own call sites — `ByShutdown` is false for a passive stdin close (claude exits 0 on EOF), so `handleChildExit` cannot tell an operator's kill from the child's own death.
- **Prompt-cache TTL is the wrong lever for a coordinator's idle gap, and is unreachable from both directions.** Top-level agents idle well past a 5-minute TTL far more than children do, but the fleet's models mostly cache implicitly (deepseek, glm, gemini) and ignore rafiki's `cache_control` breakpoints entirely — measured, the addressable cost of every cache lapse across fundi traffic was near zero. The plan's own shape keeps it closed: coordinators run on cheap implicit-caching models by design, and `--kind claude` subagents set their OWN `cache_control` (rafiki proxies those requests without assembling them, so `pkg/llm`'s `CachePolicy` never governs them). Re-open only for a fundi agent explicitly pointed at an Anthropic model — re-run the gap/miss numbers first, since `conversations.model_pricing` has a single `cache_write_usd` column that would mis-price a mixed-TTL rollout, and a `max_tokens: 0` keep-alive is closed here because it's rejected alongside `thinking.type: "enabled"`.
- **The agent-control preference must be asserted in TWO channels, not deferred to the client's native tool.** MCP tool descriptions must assert the preference for `agent_spawn` over Claude Code's own `Task` tool outright (pinned negatively by `TestMCPFaceDescriptionsDoNotDeferToTheNativeSubagentTool` — a carve-out for "lightweight" delegation loses outright against the client's own system prompt) AND daemon-spawned claude children get `claudeargv.CoordinationPrompt` merged into `--append-system-prompt` from both spawn paths. The flag is LAST-WINS, so the merge must stay one element carrying both texts; a respawn must not double-append, since the childstore session keeps the caller's original prompt and the merge happens at argv-build time.
