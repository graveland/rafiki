# rafiki — project instructions

**This file is a lookup table, not a diary.** Update it when you learn a gotcha, an architectural invariant, a footgun, or a convention that isn't obvious from the code — but write the *current rule and where it's enforced* (file, test, symbol), not the story of how you found it. Concretely:

- No dates, version numbers, or "this shipped wrong once" incident narration — git history already has that; this file only needs the fact and where to verify it.
- One entry per invariant. Before adding one, check whether an existing entry already covers it, and extend or replace that entry instead of appending a near-duplicate.
- Prune in the same edit that makes an entry stale: when the underlying code changes or a rule gets superseded, delete or rewrite the entry — don't leave it next to a newer one it now contradicts.
- If a rule needs more than ~5 lines to state, it likely belongs in a doc under `docs/reference/` with a one-line pointer here instead.
- Skip exhaustive test-name enumeration; naming the package (or one representative test) is enough for a reader to find the rest.

- **Three binaries, split by dependency: `rafiki` is a socket client that must never open a postgres connection; `rafikid` owns every DSN; `rafiki-hooks` is the internet-facing webhook gateway and links neither pgx NOR daemon code.** `cmd/rafiki` links zero pgx packages, enforced by `TestClientDoesNotLinkPostgres` (`cmd/rafiki/no_postgres_test.go`); its sibling `TestClientDoesNotLinkOIDC` pins the same split for the Login flow. `cmd/rafiki-hooks` carries `TestHooksDoesNotLinkPostgres` and `TestHooksDoesNotLinkDaemon` (`cmd/rafiki-hooks/no_postgres_test.go`) for the same reason, one notch stricter: a DSN or a daemon package in that image is a security boundary crossed, not untidiness. The daemon-link guard asserts on the explicit `daemonOnlyPackages` list, because `cmd/rafikid` is `package main` and can never be a dependency — a check naming it can never fail, so a NEW daemon-only package belongs on that list. All four guards FAIL, never skip, when the Go toolchain is missing from `PATH` — a guard that silently skips is not a guard. `rafiki` is also the executor (`rafiki executor serve`) — `pkg/executor`, `pkg/executors`, and `pkg/routing` are pgx-free too, which is what lets the client import them. The client asks the daemon for model info over the `ModelInfo` RPC rather than reading the OpenRouter catalog itself.
- **`rafiki-hooks`' security property is the ORDER of its request checks: path → that route's secret, `MaxBytesReader` bound, constant-time verify (`hmac.Equal` for the signature schemes, `subtle` for a generic header), then parse** (`cmd/rafiki-hooks/handler.go`). The 2xx for a DELIVERABLE event is written only after `Notify` returns, and the delivery id is recorded only then; refusals (404/405/413/400/401) and the no-op `200`s (`ignored`, `duplicate`) are answered without calling `Notify`. The fragment's charsets and caps live in `pkg/notify`, stdlib-only, and BOTH sides import it — the gateway via `notify.ValidSource` for `notify_source` (`TestNotifyImportsStdlibOnly`, `TestRouteValidateNotifySource`).
- **`rafiki setup` reaches the database only by exec'ing `rafikid`** (`migrate`, `user create`, `user token mint`), with the DSN in the subprocess ENV, never argv (`cmd/rafiki/setup_db.go`, `setup_identity.go`); setup-owned daemon settings live in `service.env` written by `paths.SetEnvFile` (replace-or-append, unlike the append-only `MergeEnvFile`) and the unit is installed with the invoking shell's daemon env captured (`installDaemonService`, `CaptureShellEnv: true`; the append-only merge never overrides what setup wrote). Saved non-secret answers are `pkg/installstate` (`install.toml`), whose keys are the future `[install]` section of rafikid.toml and are never renamed.
- **Releases are verified against `pkg/relsign.TrustedKeys`, an embedded ed25519 key list; `rafiki upgrade` installs nothing whose `checksums.txt.sig` does not verify, and verifies before it downloads the archive.** Each key carries `MaxVersion` (the last release tag it may sign; empty on the current key). Retiring a key means shipping a release, signed by the new key, that sets it (`v0.0.0` revokes); keys are never removed. Signing is `cmd/relsign` through goreleaser `signs` with the `RELSIGN_KEY` secret; a `signs` entry's `env:` is rendered with an EMPTY `.Env` map (goreleaser v2), so the key cannot be templated in there — the sign subprocess inherits the goreleaser process environment, and the release workflow sets `RELSIGN_KEY` on the goreleaser step. `RELSIGN_KEY` is an ENVIRONMENT secret on `release`, never a repository secret (a repo secret reaches every workflow in the repo, and it silently serves any job that omits `environment:`); the environment's deployment rule must be restricted to `v*` tags, or `environment: release` is only a label. The seed cannot be recovered — keep a copy off GitHub. `relsign.Verify` is the only verifier; pinned by `TestVerifyMaxVersionBounds` (`pkg/relsign`) and `TestStageReleaseRejectsBadSignature` (`cmd/rafiki`).
- **`fundi` is not a retired name — it names the native agent runtime**, one of three child kinds. `pkg/fundi/`, `protocol.KindFundi`, `--kind fundi`, and `rafikid fundi` are all correct and must survive any sweep.
- **`make test` relies on the go test cache, so anything a test hands to a subprocess must be opened by the test to count.** `test/integration` builds `rafikid`/`rafiki` in `TestMain`; its cache key covers their sources only because tests reach the binaries through `daemonBinary()`/`cliBinary()`, which open every build input (`test/integration/buildinputs_test.go`). Never use `binaryPath`/`cliPath` directly, and add any new subprocess fixture to `listBuildInputs`. Opens in `TestMain` before `m.Run()` are not recorded.
- **`RAFIKI_TEST_DSN` points at the disposable `pg-test` docker container (127.0.0.1:5433, tmpfs, fsync off), not the `pg` container on 5432** — scratch-database drops there cost ~20ms instead of ~1s. It loses everything on restart, and the entrypoint recreates `rafiki_test`. Leave `pg` for real data. **It does NOT reset between runs, and the whole suite shares it** (`dropDaemonRows`' doc comment, `test/integration/db_child_state_test.go`), so a DB-backed test must be idempotent across runs: never assert on a global row count, and never search for a fixed literal term you insert — every earlier run's rows are still there. `seedRecallWindow` (`test/integration/child_recall_test.go`) is the worked example: a per-run unique term plus a `t.Cleanup` that deletes what it inserted.
- **`go test -run` is an UNANCHORED substring match, so a verify command silently skips tests its pattern doesn't prefix.** Check that every required test name actually contains the `-run` pattern before trusting a green run. When a pattern and a set of pinned names conflict, a pattern-prefixed shim whose subtests call the pinned bodies (`t.Run("…", TestPinnedName)`) satisfies both.
- **`pkg/execpool`'s `TestStreamLimitWaitsRatherThanFails` can hang until the whole package times out (10m), on an untouched `main` as much as on a branch** — an in-memory http2-over-`net.Pipe` transport test, so the hang is environmental, not a code failure. Before debugging a `make check` timeout that names only `pkg/execpool`, run that one test on `main` and compare. Treat it as the sole failing package or not at all.
- **This dev environment wraps `go test` (and other dev commands) through `rtk`, which compacts output to a bare pass count** — SKIP lines are swallowed, so a suite that silently skipped everything looks identical to one that passed. For real test output (verifying a test ran, reading a panic trace, `-json`), invoke the toolchain directly: `/usr/local/go/bin/go test ...`.
- **A non-interactive shell on this machine lacks `/opt/homebrew/bin`, and `fundi.BuildRuntime` hard-requires `rg` on PATH** — so `make check` from a bare shell fails ~40 engine-spawning tests (pkg/fundi, pkg/inproc, pkg/executor, cmd/rafikid, test/integration) with `ripgrep (rg) is required but was not found on PATH` or children that exit at startup (`0 live executor(s)`, prompt-delivery timeouts). Prefix `export PATH=/opt/homebrew/bin:$PATH` — treat that signature as missing-rg, not a code failure. `uv` is likewise absent: the python-SDK integration tests SKIP. `make proto` needs the same prefix plus the freshly built plugin dir: the executor.proto invocation resolves `protoc-gen-go` by NAME on PATH (no `--plugin=`), so export `PATH="$PWD/bin:/opt/homebrew/bin:$PATH"` or it dies with `protoc-gen-go: program not found or is not executable` — the plugins are built into the gitignored `bin/` by the proto target itself.
- **Setting `Accept-Encoding: gzip` by hand on an outbound request DISABLES Go's transparent decompression.** `http.Transport` only gunzips when the request's header is empty; set it yourself and you get raw gzip bytes with no error. A fixture server answering plain JSON can't catch this — a test must actually gzip its body and set `Content-Encoding: gzip`.
- **Deleting a git worktree leaves golangci-lint's cache keyed to the dead path, and the next `make check` in a different worktree reports phantom failures** citing files by their old absolute path plus `failed to parse file` warnings. `golangci-lint cache clean` fixes it. Suspect this whenever `make check` fails on code you didn't touch, especially right after `git worktree remove`.
- **The migration chain must be contiguous 1..N, and `Migrate` skips by version NUMBER, not name.** `loadMigrations` hard-fails on a gap or duplicate — check the max version in the TARGET database before adding a migration, not just the highest file on your branch, or two branches can silently claim the same number.
- **Isolating a scratch daemon means isolating a PROFILE under an isolated `XDG_CONFIG_HOME`, not an env var.** `pkg/profile` is the only resolver: `-P` > `$RAFIKI_PROFILE` > the `current-profile` pointer > bootstrap. `RAFIKI_URL`/`RAFIKI_TOKEN`/`RAFIKI_SOCKET`/the three `RAFIKI_DEFAULT_*` vars are hard client-side errors (`profile.CheckRetiredEnv`), because each was a global that couldn't serve two daemons. `rafiki executor serve` is exempt structurally (it never calls `newConnectEndpoint`) — don't add the guard to the root command's `PersistentPreRunE`, that breaks it. Scoping rule for new settings: per-profile is the default; global is only for properties of the person that no daemon influences (`configKey.global` — currently just currency). Two still-true traps when isolating a scratch daemon: it does not migrate on startup (a fresh database logs `relation "conversations.child" does not exist` and carries on degraded), and `make check` reads the working tree, so nothing may edit it concurrently — capture the gate's exit code directly (`make check > log; echo $?`), since `make check | tail` reports tail's exit code instead.
- **No `Co-Authored-By` trailers in commit messages.**
- **`make check` (vet + golangci-lint + unit tests, `-race`) is the only gate — there is no CI on this repo.** Run it before considering anything done.
- **Tests assert with `github.com/multigres/testkit/assert`; `Eq` is `comparable`-generic and refuses `[]byte` and non-comparable types** — use `EqDeep`/`EqDiff` for byte slices and structs, and note `Collecting.Greater` takes `(bound, value)` (asserts value > bound), the reverse of the stdlib reading order.
- **DB-backed tests silently skip without `RAFIKI_TEST_DSN`** — a green `go test ./...` does not mean the store/insights/agentcli code was exercised. Source `.env` first (`set -a; . ./.env; set +a`) and check the skip count, not just the exit code. The inverse signature is environmental too: every DB package failing at once with `database "rafiki_test" does not exist` **at 127.0.0.1:5432** means the run dialled the wrong server (the `pg` container, not the disposable `pg-test` on 5433 that `.env` names) — the process did not have the documented DSN; re-run one DB package directly with the sourced `.env` before debugging code. `pg-test` is tmpfs and disposable, so after a container reset recreate the seed db: `docker exec pg-test psql -U postgres -c 'CREATE DATABASE rafiki_test'`.
- **`agent_spawn`'s `cwd` does not isolate a child — verify the worktree, never assume it.** A child spawned with `cwd=<worktree>` can still end up split-brained: file tools write into the worktree while bash verifies/commits in the main repo, which is misread as the edit tool silently losing writes and can end in a commit directly on `main`. Every dispatch needing isolation carries an explicit block: `cd <worktree> &&` first on every bash call, absolute paths under the worktree for edit/read/write, a `pwd`+`git rev-parse --show-toplevel`+`git branch --show-current` check before the first edit (blocked on mismatch) and again before committing. Settled-but-unreaped children still count against the live-agent cap — `agent_kill` finished workers before spawning more.
- **`make check` in a fresh git worktree fails at `test/integration` with every test reporting "daemon never accepted"** — the worktree has no gitignored `.env`, so `RAFIKI_TEST_DSN` is unset and the harness can't start daemons. Reads exactly like a daemon regression. Source the main checkout's `.env` first (`set -a; . <main-checkout>/.env; set +a`) and treat that signature as missing-env, not a code failure.
- **gofmt realigns the WHOLE `const`/`var` block, not just new lines** — adding a longer identifier to an aligned block and hand-aligning only your own addition leaves pre-existing lines gofmt-dirty. Run `gofmt -w` (or golangci-lint's `gofmt` linter) after touching an aligned block, not just `go vet`.
- **In this dev environment, gopls/editor diagnostics claiming "BrokenImport"/"undefined"/"module not in workspace" are frequently false positives** from a stale workspace resolution issue, not real compile errors. Trust `go vet ./...` / `go build` / `go test` from a real shell over IDE-style diagnostics.
- **`pkg/protocol` is a deliberately STDLIB-ONLY package** (no third-party import — `bufio`, `bytes`, `errors`, `io`, `encoding/json`, `time` today). It holds the domain types, the child kinds, the `Err*` reason vocabulary (what rides a Connect error's `ErrorInfo`), and `FrameReader`/`WriteFrame` — no wire protocol of its own any more. Stdlib-only is what keeps `TestClientDoesNotLinkPostgres` green, and `pkg/protocol/epoch_test.go` pins the import set. Don't mirror a domain type's fields into a parallel one: mirroring types nobody enforces stay in sync is pure drift risk.
- **Watch for zero-value traps: an enum whose zero value is a meaningful default rather than an explicit "unset" sentinel is reachable by an ordinary Go mistake** (a zero-valued struct literal, a fixture forgetting a field, a constructor that never sets it) — not just by a deliberate choice. `inbox.ModePrompt` (see its doc comment in `pkg/inbox/inbox.go`), `protocol.SpawnRequest.MaxCost == 0` meaning unlimited (daemon-state-and-recovery skill), and `ChildSummary.LatestOrdinal == 0` conflated with unset — ordinals start at 0, so a one-event log was silently skipped (fixed by returning `(int32, bool)` from `latestOrdinal`, `cmd/rafiki/history.go`) are the three that already bit us; check any new enum in this repo for the same shape before it ships.
- **Presets resolve ONCE, in `Controller.Spawn` (`applyPreset`, `cmd/rafikid/presets.go`); resume never re-resolves** — the resolved fields live on `childstore.Session`, and a preset edit must not reach a running or resumed child. Preset allowlists (`tools`/`skills`/`mcp_servers`) are tri-state end to end (SQL NULL / Go nil / JSON absent = all; `'{}'` / non-nil empty / `[]` = none), pinned by `TestPresetStoreTriStateRoundTrip` (`pkg/presetsdb`) and `TestPresetProtoRoundTripTriState` (`pkg/presets`); collapsing nil and empty turns "all tools" into "no tools".
- **Every skill-set write goes through `skills.Store.PutSet` under the `skillsWriteLockKey` advisory lock (`pkg/skillsdb`); it never updates `enabled` and never writes another source's row.** `PutSet` replaces exactly one `(owner, source)` set, refuses a namespace another source holds in the same layer (`NamespaceHeldError`), and returns `changed=false` for a byte-identical set so nothing is pushed. `SetEnabled`/`Delete` act on a row id after `skills.Resolve` picks the row. Pinned by `TestPutSetConcurrent` and `TestPutSetPreservesDisabled` (`pkg/skillsdb`).
- **Skill layering is `skills.Resolve` (`pkg/skills/resolve.go`), the only place precedence is decided; the claude push and fundi spawn both call it.** core → global → user: a namespace present in a layer (any row, enabled or not) replaces that namespace from every lower layer whole, except `rafiki`, which merges per name; disabled rows are dropped last. Pinned by `TestResolve*` (`pkg/skills`).
- **A repo job runs from `OpenRepoCheckout`'s resolved commit dir and holds its flock for life; never join `repos.CacheDir()/<name>` directly.** `current` is a symlink flipped only after a refresh's checkout, venv and discovery succeed, and the sweep takes the exclusive side of `<dir>/.rafiki-inuse`, so a held commit (and its venv) survives any number of refreshes. Pinned by `TestRepoHoldKeepsOldCommit` (`pkg/executor`).
- **A connectapi `Set*(m T)` setter must refuse nil before storing `&m`**: storing the address of a nil interface makes `Load()` return a non-nil pointer to a nil manager, defeating the unwired `Unavailable` path and nil-panicking the first handler call. `SetSkillManager` and `SetPymoduleManager` do this, pinned by their `TestSet*ManagerNilIsRefused` tests (`pkg/connectapi`); follow them when adding the next setter.
- **Spans are built only by `pkg/turntrace`, fed from `publishEvent`; content leaves the daemon only through `pkg/telemetry`'s capping functions.** No runtime builds turn/tool spans itself, and nothing else writes prompt, reply or argument text onto a span. Errors are the deliberate exception: always exported, capped only for size (`telemetry.ErrorText`). Pinned by `TestContentGatedByPolicy` and `TestErrorsAlwaysRecorded` (`pkg/turntrace`); see `docs/reference/telemetry.md`.
- **Design/plan docs live in `docs/plans/YYYY-MM-DD-<topic>-design.md` and `...-plan.md`** (not the generic `docs/superpowers/` default).
- **Generated protobuf code is checked in** (`pkg/executorpb/`). `make proto` regenerates it when the `.proto` file changes; never hand-edit `.pb.go`/`.connect.go`.
- **`pkg/protocol` must never import `pkg/executorpb`.** The protocol package promises zero dependencies; the executor protocol is a separate wire format with its own types and transport.
- **The Connect control plane is the ONE daemon↔client plane** (proto/rafiki/v1/control.proto, served by `pkg/connectapi` on the UDS and the TLS listener; see `docs/reference/control-protocol.md`). Identity is resolved per connection: nil identity (the unix socket, local trust) passes every policy; a user credential passes everything it is entitled to; any child credential is bounded by the policy interceptor (`cmd/rafikid/connect_policy.go`) and `scopeFor` (the conversation verbs' scope derivation). Presets and other owner-scoped state resolve against the connection's owner: a profile's bearer token rides the transport (`bearerTransport`), never a per-call header, and an unknown token is refused `Unauthenticated` ("invalid auth token" — the `Login` service excepted: it mounts outside authentication, next entry) — never silently downgraded to anonymous; a store outage is `Unavailable`. A profile that is token-less stays anonymous locally. Recovery is `rafikid user create <name> --token` for a NEW user, or `rafikid user token mint <name>` for an existing one (direct DSN, no daemon, no credential needed), and the admin bit comes ONLY from `rafikid user create <name> --admin` on the daemon host — Connect's `CreateUser` can never mint an admin, and a daemon with zero users logs that once at startup. Pinned end to end by `TestCLI_PresetPutThenCreateOnTheSameProfile` (test/integration).
- **The `Login` Connect service is mounted OUTSIDE authentication on both mounts** (`server.Handler.Login`, `pkg/server/handler.go`, registered by `Mount` without the auth wrap; the UDS login route in `cmd/rafikid/connect_uds.go`, with no interceptors — deliberately not through `connectControlRoute`), because re-login must work with no credential or an expired one: an unknown bearer on `/rafiki.v1.Login/` reaches `BeginLogin`, never `Unauthenticated` (pinned by `TestServeConnectUDSLoginReachesBeginLoginWithUnknownBearer`, `cmd/rafikid`). It never reads identity and is not in `connectPolicyTable` — that gate scopes `/rafiki.v1.Control/` only. OIDC identities bind once by email and resolve by `(issuer, subject)` afterward (`usersdb.ResolveOIDC`); lookups are scoped to the configured issuer.
- **One wire protocol: Connect/protobuf for daemon↔client AND daemon↔executor.** Cross-boundary constants have drifted before (`APP_NAME` across Go and TypeScript). When you change a workspace or isolation value on one side, grep the other.
- **Time on the wire is `google.protobuf.Timestamp`/`Duration`, and the wire carries a protocol epoch.** No proto field is a unit-suffixed int or an RFC3339 string; `protocol.Epoch` (`pkg/protocol/epoch.go`) is bumped on every wire-breaking change and refused loudly by `pkg/server.RequireEpoch` (Connect, both mounts, `Login` included), `pkg/upgradeconn` (executor/daraja, a plain 400) and the client transports; stored events decode with `DiscardUnknown` and a `created_at` fallback (`pkg/eventlog`). Pinned by `TestEveryRafikiV1RouteIsGatedOnBothMounts` (`pkg/server`) and `TestReadOldPayloadWithRemovedFieldsStillDecodes` (`pkg/eventlogdb`).
- **The executor and daraja links authenticate ON the HTTP Upgrade request, before hijack** (`upgradeconn.Handler`'s `authorize`; `Authorization: Bearer|Enroll|Ticket`, minted credentials on the 101's `Rafiki-Credential`). A refusal is a plain HTTP status (401 terminal, 503/409 retried) and must never hijack; there is no hello frame. Client rule: 400/401/403 terminal, anything else retried. Pinned by `TestUpgradeAuthRefusalIsAnOrdinaryResponse` (`pkg/upgradeconn`).
- **The daemon learns of executor job exits by push, never by polling.** One `WatchJobs` stream per executor connection (`pkg/execpool/watch_jobs.go`); `Controller.handleJobEvent` hands the fragment to the event buffer, which persists it to the durable inbox, and only then calls `AckJobExits`; the executor replays unacked exits on every subscribe and never evicts them. Push-before-ack is the no-loss rule.
- **Generated protobuf code in `pkg/gen/` is committed and regenerated by `make proto`; never hand-edit a `.pb.go`.** `ToolUse.input_json` is an opaque JSON string (typing it would mean regenerating the schema per tool change), and `ToolResult.content` is a repeated `ContentBlock`, not a string (flattening it would make multimodal tool output a breaking change later). Every `Usage` field is `optional` because a zero `cache_write` must stay distinguishable from "not reported" — collapsing them silently poisons cost math and `ProviderGuard`'s evidence.
- **Adding an RPC to `proto/rafiki/v1/control.proto` breaks `pkg/connectapi` compilation the moment `make proto` runs.** `connectapi.Server` implements the generated `ControlHandler` interface directly (no `UnimplementedControlHandler` embed), so a new `rpc` line adds a method the tree won't compile without — sequence the proto change and its handler into one task. Extending a `connectapi` interface forces stubs on every test implementer of it; enumerate them with the COMPILER (`go build ./... && go vet ./...`), not a grep — a grep has missed fakes twice.
- **An optional capability interface asserted OFF the `ChildLifecycle` at runtime is invisible to the compiler when the wired adapter drops it.** Production wires `connectLifecycle` (`cmd/rafikid/connect_adapters.go`), not `*Controller`; the only such seam today is `DescendantLister` (`pkg/connectapi/cascade.go`), and its forwarder missing there answered every `include_descendants` request `unimplemented` while the Controller supported it. Any new runtime-asserted lifecycle seam must be pinned in `TestControllerSatisfiesConnectSeams` (`cmd/rafikid/connect_wiring_test.go`).
- **Every Control RPC must be classified in `connectPolicyTable` (`cmd/rafikid/connect_policy.go`) — the completeness test fails otherwise.** `connectPolicyInterceptor`, mounted on BOTH Connect mounts through `connectControlRoute` (proxy face + `connect_uds.go`; never call `connectapi.Server.Routes` directly for the Control service), maps procedure → policy: `userOnly` (default, fail-closed), `anyCaller` (read-only non-scoped: ListModels, ListPresets, GetPreset, GetRateLimitStatus, ListRoutes), `childScoped` (subtree authority: the handler bounds a `ProvenanceChildToken` caller via `ChildScopeSource` — the childstore parent chain through `childstore.IsDescendant`, wired in `cmd/rafikid/connect_childscope.go`; the three script verbs are identity-POSITION instead — `Report` acts on the caller's own parent, `Receive`/`SetResult` strictly on the caller itself; `ConversationSearch`/`Export`/`Query` answer a child from its own subtree via `childConversationScope`, `SetBudget` from a child is `SetChildBudget`'s direct-parent rule, never operator authority; the four pymodule verbs read/write the owner's corpus; `PutPreset`/`DeletePreset` admit only a top-level child — `topLevelChild`, shared with the MCP face's `presetStoreForChild` and fundi's binding), `ownerScoped` (the caller's OWNER's data: Recall, RecallContext, GetMemory, MemoryTree, PutMemory, DeleteMemory; the gate admits `ProvenanceChildToken` only, and the handler resolves the owner's NON-admin identity via `recallOwner` — `cmd/rafikid/recall.go` — so a child of an admin never reads daemon-wide; no subtree check). A child credential on Connect gets exactly what the MCP face (`mcp_face.go` `getServer`) gives it — change both or neither. A nil identity (UDS local trust) passes; any non-user identity — per-child secret, per-boot + session, or the EMPTY `Identity{}` a bare per-boot token yields — is a child credential and is refused on everything but `anyCaller` and `childScoped`/`ownerScoped`-with-child-provenance. `TestControlPolicyTableCoversEveryProcedure` walks the generated descriptor, so a new RPC lands only with a table entry; `scopeFor` (conversation scope) stays separate. The one admission the table does NOT decide is `ProvenanceNotify`'s — a branch ahead of it, never a policy row (see the `identityFromStoreRow` entry below). The who-may-call-what table lives in `docs/reference/control-protocol.md`.
- **A token's capability set becomes a provenance in ONE place, `identityFromStoreRow` (`pkg/server/usertoken.go`), and only two shapes are honoured: NULL = `ProvenanceUser`, exactly `{notify}` = `ProvenanceNotify`.** Any other non-NULL set is refused as an INVALID token, never widened to full authority; `ProvenanceNotify` is admitted to `Control.Notify` alone, by a branch at the TOP of `authorizeControlProcedure` plus `UserTokenAuth.Middleware`'s 403 on every other path. Pinned by `TestNotifyProvenance*` (`pkg/server`) and `TestNotifyTokenRefusedOnEveryOtherProcedure` (`cmd/rafikid`). Column, tri-state, oidc refusal and the deploy-order rule: `docs/reference/control-protocol.md` "Who may call what".
- **A child's recall identity is its owner's non-admin identity, on every face.** `recallOwner` (`cmd/rafikid/recall.go`) is the only place an identity's admin bit reaches a recall binding, and it grants admin only to `ProvenanceUser`; the MCP face and `connectRecall` go through it, while the fundi runtime builds the same non-admin `users.Identity{UserID: ownerUserID}` itself (`cmd/rafikid/agent_runtime.go`). `TestChildRecallIdentityNeverAdmin` (`cmd/rafikid`) pins the admin clause at the identity level; `TestChildRecallOfAdminOwnerIsNotDaemonWide` (`test/integration`) pins the end-to-end flow.
- **`RAFIKI_URL` has to be resolved through the profile, per COMMAND.** `newConnectEndpoint` (`cmd/rafiki/connectclient.go`) is the one place the CLI resolves an endpoint — a verb that bypasses it gets no benefit from an operator's profile. The credential rides the transport (`bearerTransport`), not a per-call header, because the `*http.Client` is handed to `pkg/tui` and never seen again; a remote endpoint with no token fails BEFORE the round trip, since this plane has no bootstrap mode.
- **Client-side preferences live in ONE document with named sections** (`pkg/clientstate`, `paths.ClientStateFile`), and writers must go through `Update` (read-modify-write) — marshalling your own section over the whole document silently drops the others. `StateDir`, not `CacheDir` (not disposable) or `ConfigDir` (not hand-edited). Everything is keyed by NAME, never enum ordinal, so inserting a column can't renumber a saved query into a different one; an unrecognised name is DROPPED, degrading the query rather than refusing it.
- **A remembered choice must never outrank a declared one.** `create`'s model chain is `--model` > `RAFIKI_DEFAULT_MODEL` > the preset's model > the model last spawned for that kind > the daemon default. The remembered value sits below both the env var and the preset deliberately — those are declarations, this is an inference. `LastModel` is keyed by kind (a `claude` child can't resolve an OpenRouter id) and an EMPTY model is never recorded, since "the daemon's default" isn't a choice worth replaying.
- **Anything that reads client state needs `XDG_STATE_HOME` isolated in tests, in three places.** `pkg/tui`'s `NewCockpit` reads the remembered query at construction and `cmd/rafiki`'s `buildSpawnRequest` reads the remembered model, so both carry a `TestMain` pointing `XDG_STATE_HOME` at a temp dir. `test/integration` execs the real CLI, and `rafiki create` records the model it spawned, so `cliCmd` must isolate it too or a test daemon's fixture leaks into the developer's real preferences.
- **`XDG_CONFIG_HOME` leaks the same way, and `providers.toml` decides where a test's LLM request actually goes.** `cmd/rafikid`'s `resolveUpstream` loads the developer's real `providers.toml` if not isolated, and a `default_provider` there outranks the senders a test explicitly registered — the symptom looks like a broken proxy branch ("all model(s) failed" / 0 requests seen), not a config leak. Both `cmd/rafiki` and `cmd/rafikid` carry a `TestMain` for this now. When an LLM-client test fails as if the request went nowhere, print the discarded error before reading any code — the host in it names the culprit.
- **Completion runs in the CLIENT and must ask the DAEMON, not dial a hardcoded socket or run local probes.** `completeChildrenByState`/`completeLabelPairs`/`completeLabelKeys` must go through `newConnectEndpoint`, the one place the CLI resolves an endpoint — a completion handler swallows every error by design, so a wrong dial fails silently as "no candidates" rather than visibly. `completeModel` must not run `models.ListSources` locally (fetching OpenRouter with the client's own credentials, probing localhost) — kind scoping lives in `cmd/rafikid`, the client keeps no copy. Any new completion helper must never exit, block past `completionDeadline`, or print.
- **CLI `-j`/`-J` JSON output is the canonical protojson of the Connect response message** (`emitProto`/`emitProtoRows`, `cmd/rafiki/protoout.go`) — no client-side output structs, no `protocol.*` output types. protojson renders `int64` as a STRING (accepted; rafiki-py sees the same) and randomises whitespace, so both helpers re-normalise through `encoding/json` to keep the bytes stable; don't string-match protojson output in new tests, and don't add a second JSON path.
- **`Spawn` fields 15–29 are operator-only, refused to child provenance** with `PermissionDenied`; the guard is enforced as the child-ALLOWED set {1–14, 30, 31} (`childAllowedSpawnFields`, `pkg/connectapi/verbs.go`), so a NEW `SpawnRequest` field is operator-only by default and must be classified on purpose — either into the child-allowed set or explicitly operator-only — or `TestSpawnRequestFieldsAreClassified` (`pkg/connectapi`) fails. Adding any Control RPC also still means a `connectPolicyTable` entry (the reflection test in `pkg/connectapi`).
- **A PROMPT whose trimmed text begins with a registered `/command` is a slash command, interpreted by the daemon before anything is persisted** (`handleSlashCommand`, `cmd/rafikid/slash_commands.go`), on BOTH the Connect `Send` path (`connectAccepter.Accept`) and the framed `Controller.Send` — so a spawn's initial `prompt` is classified too (`agent_spawn` with `prompt:"/exit"` kills the child it just spawned). STEER/ABORT text never is; an unregistered `/foo` stays an ordinary prompt; a registered command a child kind does not support is `InvalidArgument`. `/exit` is `Kill` (resumable) and queues nothing; `/compact` (claude) forwards as a prompt; for fundi both `/compact` and `/clear` are queued untouched and executed by `Engine.runSlash` (`pkg/fundi/engine.go`) in queue order; `/clear` (claude) marks `conversation.clear_pending` and arms `Controller.clearExpected`, consumed once by `refuseClaudeSessionIDChange` to adopt the new session id. See `docs/reference/control-protocol.md` and the daemon-state-and-recovery / claude-code-integration skills.
- **The client CLI's output contract is three-way, and there is no pipe→JSON auto-switch.** `--output auto` (default) renders a table on a TTY and a pipe alike — `resolveOutputMode` never probes for a terminal. `-o json`/`-j` for pretty JSON, `-J`/`-o jsonl` for one compact record per line (`emitProtoRows`, `cmd/rafiki/protoout.go`; any `{"rows": …}` envelope unwrapped), `-j -J` together errors. Failures go to stderr, successes to stdout. `rafikid agent` is NOT on this contract — its `-j`/`-J` mean indented/compact JSON with the envelope included, and both set means indented wins.
- **All CLI tables render through `pkg/table` (lipgloss v2); go-pretty is removed from go.mod** — do not add it back. `Width 0` on a pipe renders every column; callers pass `Drop` if they want a width cap.
- **`make check` is not hermetic against an exported client env var — isolate it, or a leaked value silently redirects the whole suite.** `test/integration`'s CLI tests spawn the real `rafiki` binary, inheriting the shell's environment. `cliCmd` blanks every retired client env var plus `RAFIKI_PROFILE` and points `XDG_CONFIG_HOME` at a fresh scratch profile naming the test daemon; unit tests use the sibling `isolateProfiles` helper for the same isolation without a subprocess. Any new test execing the CLI belongs on `cliCmd`; any new in-process `cmd/rafiki` test belongs on `isolateProfiles`. Daemons booted by the harness (`bootDaemon`, `bootDaemonDB`) get `noRealProviderEnv()` by default — a real `OPENROUTER_API_KEY` from `.env` wires the live OpenRouter provider directory and changes behaviour (made-up provider slugs are refused); a test needing a key passes it in `extraEnv`, which wins.
- **A finished conversation is `conversation.closed_at IS NOT NULL`; a closed child is `child.closed_at` (the close tombstone, formerly `deleted_at`).** Kill never sets either. Claude children leave `child.conversation_id` NULL — their conversations link by `external_ref = child_id` or `child_id:<thread>`; any child↔conversation join must use all three arms (`Controller.Close` stamping, `pkg/recalldb`'s stopped/eligibility SQL). Escape `_` in the LIKE: child ids contain it. Two families of read treat closure oppositely: LIVE-STATE reads (the agent list, `MaxChildren`, recovery, any verb acting on a live child) use live rows only, while LINEAGE reads (a child credential's subtree conversation scope, subtree spend, budget enforcement) cover live AND closed descendants — closure never drops a child from its ancestors' lineage. Lineage reads go through `Controller.subtreeSelector` (`cmd/rafikid/limits.go`) over `childstoredb.Store.Lineage` and fail closed on a lineage error, never an empty-and-allowed scope. Closure is written down before it is forgotten: `Close`/`CloseAllExited` persist the child's snapshot (`writeRecord`) before the tombstone and FAIL CLOSED on a persist error, and a fresh spawn whose initial row cannot be written is REFUSED (`cmd/rafikid/controller.go`; a nil store keeps best-effort) — no child runs without a row — so a closed child's `session_id`/`conversation_id` never leave its ancestor's lineage. `Lineage` errors on genuine label ambiguity (a returned row's `labels` not a JSON object, or a parent/root key present but not a string) and ignores unrelated non-string labels. Pinned by `TestSubtreeSelectorIncludesClosedDescendants`, `TestClosePersistsSessionIDBeforeTombstone` and `TestSpawnRefusedWhenInitialRowCannotBePersisted` (`cmd/rafikid`) and `TestClosedLineageChildCredentialStillSearchesAClosedDescendant` (`test/integration`).
- **The daemon's own LLM jobs are captured as conversations** (`llm.Client.Conversation` writes rows). Anything that indexes or summarizes conversations must exclude `recall.ExcludedEntrypoints` (`recall-summary`, `analyze`), or the summarizer summarizes its own output forever.
- **Recall's derived tables (`conversation_window`, `conversation_summary`) may be rebuilt/replaced; `memory` is source data and is tombstoned (`deleted_at`), never deleted.** Embeddings record `embedding_model`; vector indexes are partial per model, created by the daemon at startup (`recalldb.EnsureVectorIndexes`), not by migrations. `child.skip_derived_index` (OR-inherited down the subtree at spawn by `inheritSkipDerivedIndex`, `cmd/rafikid/controller.go`) makes the indexer skip embedding and summarising a child's conversations — `conversation.derived_skip` is set by `WriteWindows` (`pkg/recalldb/indexer.go`) at first extraction and again by `MarkDerivedSkip` in the summarizer immediately before summarising each of its ≤5 candidates (`pkg/recall/summarize.go`; both run the shared `markDerivedSkipSQL`), and read by the indexer's pending queries (`AND NOT c.derived_skip`), windows and BM25 unaffected; pinned by `TestSkipDerivedIndexGatesEmbedsAndSummaries`, `TestSkipDerivedIndexPendingQueryIsFast` and `TestSummarizerSkipsFlaggedConversationNotYetExtracted` (`pkg/recalldb`).
- **Prod's `rafiki` role is not superuser; `vector` and `pg_textsearch` are untrusted extensions** — a migration adding an untrusted extension needs a superuser to `CREATE EXTENSION` first (and `pg_textsearch` in `shared_preload_libraries`). The test DB runs as superuser, so tests cannot catch this.
- **A non-empty child name is unique among an owner's live siblings, and the `child_sibling_name_live` index is the authority — never a pre-read.** A violation is `childstore.ErrNameTaken` only from `isSiblingNameViolation` (that SQLSTATE AND that constraint name; `pkg/childstoredb`), every 23505 otherwise stays internal. Admission pre-reads with `NameHolder` — the same predicate, and the same emptiness test (`name == ""`, not TrimSpace) — but the index is the backstop: a lost race aborts the spawn through `abortSpawn` and answers "taken concurrently; retry". Only `SpawnRequest.SuffixNameOnConflict`, set by the two tool spawners, suffixes. Pinned by `TestSiblingName*` (`cmd/rafikid`), `TestSiblingNameIndex*`/`TestNameHolder*`/`TestIsSiblingNameViolation` (`pkg/childstoredb`), `TestMigrate0054RenamesLiveDuplicates` (`pkg/store`). Messages, the suffix range, the migration's rename pass and its deploy note: `docs/reference/control-protocol.md` "Child names are unique among live siblings".
- **`budgetHalted` (`cmd/rafikid/budget_halt.go`) is the single over-budget predicate: the child or any ancestor in the breach set.** Scheduled fires, the MCP face's tool gate for child callers (`cmd/rafikid/mcp_budget_gate.go`), fundi's `EngineConfig.Halted`, and the inbox all consult it; any new path that starts agent work must too. The inbox splits by who is waiting: a direct prompt/steer is REFUSED with `ErrBudgetExhausted` before anything persists (`acceptAndDeliver`, `cmd/rafikid/inbox_wiring.go`), while a daemon-pushed prompt-mode row (job exit, subagent report) is HELD pending by `deliverInbox` (`errInboxBudgetHeld`) and released by `releaseHeldInbox` wherever a breach clears (a raise in `applyBudgetChange`, the sweep) — steers stay exempt because the breach notice is one, and the queue stops at the first held batch so a steer queued behind a held prompt waits too. The engine's `runTurn` is the backstop for a halt that lands after delivery: it appends the prompt and makes no LLM call (`TestHaltedChildRunsNoLLMCallButKeepsThePrompt`, `pkg/fundi`). The breach set is in-memory: `seedBudgetBreaches` marks it (without steering) at the end of the boot walk.
- **The display state (`working`/`waiting`/`failed`/`idle`/`exited`, `waiting_on` operator/schedule/job/children/events) is DERIVED by one function, `computeDisplayState` (`cmd/rafikid/display_state.go`), and `Status` is never a display value: `Status` is recovery's resume signal. Only a top-level, non-script child's `agent_report kind=question` sets the stored `pending_question` (cleared at turn start in `handleStatusChange`); a mid-tree child's question goes to its parent. No consumer re-derives it.** Pinned by `TestComputeDisplayState*`.
- **A change under `web/` or to `proto/rafiki/v1/control.proto` must pass `make check check-web`**: `make check` is Go-only and stays green while the generated TS client breaks the web build. `check-web` needs node + pnpm + protoc on PATH (`/opt/homebrew/bin`).
- **`pkg/webui` is a message-unaware passthrough and the browser never holds a daemon credential** — no RPC allowlist (the localhost gate is the boundary: Host/Origin checks + the single-use launch code → `X-Rafiki-Web` session secret, never a cookie because cookies are host-scoped, not port-scoped), `/rafiki.v1.Login/*` is never proxied, gate refusals carry `Rafiki-Web-Gate: refused` so the UI can tell them from a daemon `Unauthenticated`. Pinned by the `TestWebui*` tests (`pkg/webui`).
