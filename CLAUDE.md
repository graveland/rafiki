# rafiki — project instructions

**This file is a lookup table, not a diary.** Update it when you learn a gotcha, an architectural invariant, a footgun, or a convention that isn't obvious from the code — but write the *current rule and where it's enforced* (file, test, symbol), not the story of how you found it. Concretely:

- No dates, version numbers, or "this shipped wrong once" incident narration — git history already has that; this file only needs the fact and where to verify it.
- One entry per invariant. Before adding one, check whether an existing entry already covers it, and extend or replace that entry instead of appending a near-duplicate.
- Prune in the same edit that makes an entry stale: when the underlying code changes or a rule gets superseded, delete or rewrite the entry — don't leave it next to a newer one it now contradicts.
- If a rule needs more than ~5 lines to state, it likely belongs in a doc under `docs/reference/` with a one-line pointer here instead.
- Skip exhaustive test-name enumeration; naming the package (or one representative test) is enough for a reader to find the rest.
- **This file is for what's relevant to nearly any task in this repo.** Subsystem-specific depth lives in `.claude/skills/` instead, invoked when a task actually touches that area — keep it there, not here:

  - `.claude/skills/daemon-state-and-recovery/` — capture, inbox, conversation leases, the conversation tree, daemon ownership/restart recovery, Claude Code thread/subagent reconstruction.

**Keep documentation in sync with code, always.** Any change to the wire protocol, CLI commands, config/env vars, or public behavior must update the relevant doc in the same change: `docs/reference/control-protocol.md` (wire protocol), `docs/agent-cli.md` (`rafikid agent` verbs), `README.md` and `docs/guide/` (architecture, setup, deployment, per-subsystem guides), `.env.example` (env vars). Documentation that drifts from code is worse than no documentation — don't defer doc updates to "later."

**A review finding is closed in the change that raised it — "parked", "follow-up" and "later" are not dispositions.** The only acceptable outcomes are: fix it; rule it out with a recorded RULING that names the scope boundary and what being wrong costs; or report it as an unresolved blocker. A deferred test gap leaves the guard it was meant to pin unenforced, a deferred doc nit ships a false statement, and a deferred defect ships. So no `TODO`/`FIXME`/`for now` comment may be added to close a review thread, and a plan's fix reserve is spent on findings rather than on a list of them. "Fixed" means a test fails when the behaviour regresses — a finding closed by prose, a name-only test, or a comment describing intent is still open. Enforcement is the completing agent's report (every finding with its disposition) and the final review auditing it.

- **Three binaries, split by dependency: `rafiki` is a socket client that must never open a postgres connection; `rafikid` owns every DSN; `rafiki-hooks` is the internet-facing webhook gateway and links neither pgx NOR daemon code.** `cmd/rafiki` links zero pgx packages, enforced by `TestClientDoesNotLinkPostgres` (`cmd/rafiki/no_postgres_test.go`); its sibling `TestClientDoesNotLinkOIDC` pins the same split for the Login flow. `cmd/rafiki-hooks` carries `TestHooksDoesNotLinkPostgres` and `TestHooksDoesNotLinkDaemon` (`cmd/rafiki-hooks/no_postgres_test.go`) for the same reason, one notch stricter: a DSN or a daemon package in that image is a security boundary crossed, not untidiness. The daemon-link guard asserts on the explicit `daemonOnlyPackages` list, because `cmd/rafikid` is `package main` and can never be a dependency — a check naming it can never fail, so a NEW daemon-only package belongs on that list. All four guards FAIL, never skip, when the Go toolchain is missing from `PATH` — a guard that silently skips is not a guard. `rafiki` is also the executor (`rafiki executor serve`) — `pkg/executor`, `pkg/executors`, and `pkg/routing` are pgx-free too, which is what lets the client import them. The client asks the daemon for model info over the `ModelInfo` RPC rather than reading the OpenRouter catalog itself.
- **`rafikid proxy record` (`cmd/rafikid/proxy_record.go`) is the one command path that needs no database** — it forwards `POST /v1/messages` to one upstream and writes byte-exact `NNNNNN-{request,response}.http` pairs, and its own path touches no config, DSN, socket, routing, auth or telemetry. Do not re-couple it: a `loadConfig`/`runDaemon`/`paths`/`pgxpool`/`server.MessagesProxy` call there defeats the diagnostic. **The process is not as isolated as the command**: `main()` runs `loadServiceEnv()` before cobra for every subcommand, so `service.env` is still read into the environment (nothing consults it, and a missing file is silent) — say that, never "reads no config file". Credential headers (`Authorization`, `X-Api-Key`, ...) are written as their scheme plus a sha256 of the token, never the token, and `metadata.user_id` (device id + account uuid) is digested the same way (`--redact-json-field` for more) — redaction is a RECORDING rule, the upstream still gets the real one; bodies stay verbatim. The record directory is a secrets artifact: `0700`/`0600`, refusal before bind and before write, and the response half is renamed SECOND, so its presence is the completion marker (`TestProxyRecord*`, `test/integration/proxy_record_test.go`). `--exec '<cmd>'` turns it into a harness (runs the command with `ANTHROPIC_BASE_URL` pointed at the bound listener, drains, exits with its status), and `rafiki claude --turn/--turn-file` drives a scripted multi-turn session in the same headless stream-json mode a claude child uses and resolves NO profile (endpoint from `--url`/`ANTHROPIC_BASE_URL`, credential from `--token`/`ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_API_KEY`) — together, one command captures a real multi-turn exchange with no daemon.
- **`rafiki-hooks`' security property is the ORDER of its request checks: path → that route's secret, `MaxBytesReader` bound, constant-time verify (`hmac.Equal` for the signature schemes, `subtle` for a generic header), then parse** (`cmd/rafiki-hooks/handler.go`). The 2xx for a DELIVERABLE event is written only after `Notify` returns, and the delivery id is recorded only then; refusals (404/405/413/400/401) and the no-op `200`s (`ignored`, `duplicate`) are answered without calling `Notify`. The fragment's charsets and caps live in `pkg/notify`, stdlib-only, and BOTH sides import it — the gateway via `notify.ValidSource` for `notify_source` (`TestNotifyImportsStdlibOnly`, `TestRouteValidateNotifySource`).
- **`rafiki setup` reaches the database only by exec'ing `rafikid`** (`migrate`, `user create`, `user token mint`), with the DSN in the subprocess ENV, never argv (`cmd/rafiki/setup_db.go`, `setup_identity.go`); setup-owned daemon settings live in `service.env` written by `paths.SetEnvFile` (replace-or-append, unlike the append-only `MergeEnvFile`) and the unit is installed with the invoking shell's daemon env captured (`installDaemonService`, `CaptureShellEnv: true`; the append-only merge never overrides what setup wrote). Saved non-secret answers are `pkg/installstate` (`install.toml`), whose keys are the future `[install]` section of rafikid.toml and are never renamed.
- **`RAFIKI_DB=embedded` is interpreted only by `resolveDSN` (`cmd/rafikid/dsn.go`), and `pkg/embedpg` is daemon-only** — every rafikid path that opens a pool resolves through it, and `cmd/rafiki` never imports embedpg (setup writes `RAFIKI_DB=embedded` into `service.env` and execs `rafikid`). The server tree is built by `build/embedpg` and released from `embedpg-v<pg>-<rev>` tags (`.github/workflows/embedpg.yml`); `pkg/embedpg/fetch.go` pins one sha256 per asset and `Version` is `<pg>-<rev>` (it keys the extracted tree, so a rebuild needs a new revision), so bumping means new pins. See `build/embedpg/README.md`. The cluster's database is `rafiki` (`embedpg.Database`), created on every resolve from `MaintenanceDSN()` (`dbname=postgres`, the one initdb makes) — `pkg/embedpg` names databases and opens none. Only the CREATE step tolerates `42P04` and `23505` on `pg_database_datname_index`, which a simultaneous second creator can lose. Provisioning must still apply the database-scoped role default `search_path=public,conversations` after finding or concurrently creating the database; `public` stays first for unqualified extension creation. `psqlInvocation` independently prepends that session default to DSN options (explicit options win), never to backup/restore invocations (`TestProvisionEmbeddedDatabaseEnsuresRoleDefaults`, `TestEmbeddedDatabaseIsCreatedOnARealServer`).
- **The embedded server's `psql`, `pg_dump` and `pg_restore` are the ones in its own tree; PATH serves every other database.** `pgClientPath` (`cmd/rafikid/db_psql.go`) is the one resolver, called AFTER `resolveDSN` has extracted the tree; `precheckPgClient` runs before it and never refuses an embedded target (nothing can be missing yet). So `backupFormatPriority` always picks the dump for embedded — a physical copy is chosen only by `--format txz|tgz`. Pinned by `TestPgClientPath`, `TestPrecheckPgClient`, `TestDbBackupFormatPriority` and the real-server `TestEmbeddedPostgresDumpRoundTripUsesTheBundledClients` (empty PATH).
- **The embedded server's extensions are installed and kept at the tree's `default_version` by `reconcileEmbeddedExtensions` (`cmd/rafikid/dsn.go`), on every resolve, embedded only.** One `DO` block under its own advisory lock reads `pg_available_extensions`, so no version lives in Go; an extension the tree does not list is skipped, a failed CREATE/UPDATE refuses the start. It installs the extension and nothing else: the `vector` columns and bm25 indexes are migration `0036`'s, so a database whose `0036` ran before the tree shipped the extensions needs its schema adapted by hand. Pinned by `TestEmbeddedExtensionsStatement` (`cmd/rafikid`) and `TestEmbeddedPostgresInstallsAndUpdatesExtensions` (`test/integration`).
- **A running embedded server is moved onto a newer tree by `Ensure`, never by the tree landing.** `Server.stale` compares the first token of the data dir's `postmaster.opts` with this tree's `bin/postgres`; `replaceStale` (`pkg/embedpg/embedpg.go`) stops and restarts it only when `Server.RestartStale` says so, and otherwise prints how to finish. `resolveEmbedded` (`cmd/rafikid/dsn.go`) allows it only when no daemon answers on its control socket (`daemonListening`), because a restart drops every open connection — the new daemon after a service restart is the normal case. Pinned by `TestStale`, `TestReplaceStaleWithoutPermissionOnlyWarns` (`pkg/embedpg`) and `TestEmbeddedPostgresMovesOntoANewBuild` (`test/integration`).
- **An embedded artifact holds only what `embedpg.ExtractTar` accepts, and no `._*` file.** PostgreSQL parses every `*.control` in `share/postgresql/extension`, so an AppleDouble sidecar (`._pgcrypto.control`, written by macOS `tar` for files with extended attributes) breaks `pg_available_extensions` and migration `0036` with it. `bsdtar` hides those entries when LISTING, so the guard in `build/embedpg/build-darwin.sh` reads the archive with python `tarfile`; `build/embedpg/smoke.sh` lists every shipped extension and fails on a stray `._*`. The tree must also keep `bin/`, `lib/` and `share/postgresql` as siblings (Postgres finds its share/lib dirs relative to the binary) and carry no hardlinks.
- **The client's pgx-link guard (`cmd/rafiki/no_postgres_test.go`) must also name `pkg/embedpg`** — embedpg imports no pgx, so a pgx-only check would let the client link the embedded server.
- **One tar extractor serves both untrusted archives: `embedpg.ExtractTar(r io.Reader, root string)`** (`pkg/embedpg/fetch.go`) is what `ensureBinaries` unpacks a downloaded build with AND what `rafikid db restore`'s `unpackDataDirArchive` (`cmd/rafikid/db_restore.go`) unpacks a physical backup with — never a second copy. Its guards: lexical `..`/absolute-name refusal, `resolveWithin` (symlink chains, dangling links), `mkdirParents` + `O_NOFOLLOW` on the final component, symlinks and directory modes created LAST, absolute/climbing symlink targets refused, every other entry type refused. `tarDataDir` (`cmd/rafikid/db_backup.go`, `checkArchivableSymlink`) applies the same symlink-target rule BEFORE writing, so a backup is never an archive its own restore refuses (`TestExtractTarRefusesAnEscapingArchive`, `TestRestorePhysicalRefusesAnEscapingArchive`, `TestDbBackupArchiveRefusesAnEscapingSymlink`). embedpg is daemon-only, so `cmd/rafikid` may import it; `cmd/rafiki` may not.
- **The embedded server listens on no TCP socket: its data dir (`paths.DataDir()/pg`, mode 0700) is the socket dir**, and rafikid stops it only inside the physical `db backup --format txz|tgz` (`runPhysicalBackup`, `cmd/rafikid/db_backup.go`) and a physical `db restore` (`restorePhysicalArchive`, `db_restore.go`) — never as a side effect. Both hold the embedpg flock across their swap/copy and both restart it on every way out EXCEPT a rollback whose own stop failed (the backup releases the flock first and the restart re-takes it); that is only true because the `db` group runs under a signal-cancelled context (`dbSignalContext`, `cmd/rafikid/db.go`), or a Ctrl-C would kill the process before the defer. A `db backup` refuses a RUNNING server without `--force` and copies a stopped one as it stands.
- **`pg_restore --no-owner` follows the connecting role, never a constant** — `restoreDumpArchive` passes it only when `connectedRoleIsSuperuser` says the role is unprivileged (it can only own what it creates); a superuser restore omits it so the archive's `OWNER TO` statements put the original owners back, which for an in-place restore is the daemon's own role. Passing it as a superuser re-owns the whole schema to that superuser and leaves the daemon with `permission denied` on its first query; a role the archive names that does not exist here fails the whole transaction rather than reassigning. Pinned by `TestDbRestoreKeepsObjectOwnershipForTheDaemonRole` (`test/integration`).
- **rafiki no longer uses TimescaleDB; `0068` converted the three hypertables and the baseline creates plain tables.** Two things still mention it on purpose: `rafiki setup`'s managed image keeps `timescaledb` in `shared_preload_libraries` because the image's own initdb creates the extension and FATALs without it (`dockerRunArgs`, `cmd/rafiki/setup_db.go`, pinned by `TestSetupDBCreateArgvPreloadsWhatTheImageAndRafikiNeed`), and the daemon plus `rafikid migrate` warn while the extension is installed (`warnLegacyTimescale`, `cmd/rafikid/legacy_timescale.go`), gated on rafiki's own three tables still being hypertables so the notice never says "can be removed" on an unmigrated database.
- **A compressed TimescaleDB chunk is INVISIBLE to an ordinary scan when `timescaledb.enable_columnarscan` is off, so `0068` forces it on for its own transaction.** Measured on 2.28.3: with the parameter set at database level, `count(*)` and `SELECT *` on a 500-row hypertable returned 495 — the copy and its row-count check read the same short table, agreed, and the `DROP TABLE` would have destroyed the rest. The migration sets the GUC transaction-locally only where it exists (`pg_settings`), and `TestMigrate0068CopiesCompressedRowsWhenColumnarScanIsOff` pins it.
- **A migration that needs an extension conditions its DDL on `pg_extension` (installed, so nothing creates it: `timescaledb`, which only `0068` consults) or `pg_available_extensions` (created by the migration itself: `vector`, `pg_textsearch`)** — which is what lets an embedded database migrate (`0036`). `TestMigrateFullServerSchemaUnchanged` (`pkg/store`) pins the available branch; `TestEmbeddedPostgresMigratesAndServes` (`test/integration`, gated on `RAFIKI_TEST_EMBEDPG=1`) pins the unavailable one against a real embedded server.
- **Releases are verified against `pkg/relsign.TrustedKeys`, an embedded ed25519 key list; `rafiki upgrade` installs nothing whose `checksums.txt.sig` does not verify, and verifies before it downloads the archive.** Each key carries `MaxVersion` (the last release tag it may sign; empty on the current key). Retiring a key means shipping a release, signed by the new key, that sets it (`v0.0.0` revokes); keys are never removed. Signing is `cmd/relsign` through goreleaser `signs` with the `RELSIGN_KEY` secret; a `signs` entry's `env:` is rendered with an EMPTY `.Env` map (goreleaser v2), so the key cannot be templated in there — the sign subprocess inherits the goreleaser process environment, and the release workflow sets `RELSIGN_KEY` on the goreleaser step. `RELSIGN_KEY` is an ENVIRONMENT secret on `release`, never a repository secret (a repo secret reaches every workflow in the repo, and it silently serves any job that omits `environment:`); the environment's deployment rule must be restricted to `v*` tags, or `environment: release` is only a label. The seed cannot be recovered — keep a copy off GitHub. `relsign.Verify` is the only verifier; pinned by `TestVerifyMaxVersionBounds` (`pkg/relsign`) and `TestStageReleaseRejectsBadSignature` (`cmd/rafiki`).
- **`fundi` is not a retired name — it names the native agent runtime**, one of three child kinds. `pkg/fundi/`, `protocol.KindFundi`, `--kind fundi`, and `rafikid fundi` are all correct and must survive any sweep.
- **`make test` relies on the go test cache, so anything a test hands to a subprocess must be opened by the test to count.** `test/integration` builds `rafikid`/`rafiki` in `TestMain`; its cache key covers their sources only because tests reach the binaries through `daemonBinary()`/`cliBinary()`, which open every build input (`test/integration/buildinputs_test.go`). Never use `binaryPath`/`cliPath` directly, and add any new subprocess fixture to `listBuildInputs`. Opens in `TestMain` before `m.Run()` are not recorded.
- **`RAFIKI_TEST_DSN` points at the disposable `pg-test` docker container (127.0.0.1:5434, tmpfs, fsync off), not the `pg` container on 127.0.0.1:5433, which serves the live `codeindex_work` database** — scratch-database drops there cost ~20ms instead of ~1s. It loses everything on restart, and the entrypoint recreates `rafiki_test`. Leave `pg` for real data. **`pg-test` carries no TimescaleDB and does not preload it** (the container runs `shared_preload_libraries=pg_textsearch` only, with the image's two `CREATE EXTENSION timescaledb` init scripts bind-mounted over by the no-op `~/.config/pg-test/noop.sh`, as `000_install_timescaledb.sh` and `010_install_timescaledb_toolkit.sh`) — preloading it made its scheduler touch every database and fail `CREATE DATABASE … TEMPLATE template1` with `source database "template1" is being accessed by other users` across the whole suite. TimescaleDB cannot be used at all without the preload, so every test whose fixture needs TimescaleDB SKIPs here through a `requireTimescale`/`requireTimescaleDB` guard — `pkg/store/migrate_0068_test.go`, `cmd/rafikid/legacy_timescale_test.go` and `test/integration/embedded_pg_test.go` — each keeping the half of its subject that needs no extension; point `RAFIKI_TEST_DSN` at a server that preloads it to run the rest. The tuner still runs on `pg-test`, so `random_page_cost=1.1` is preserved: without it `pkg/childstoredb/TestLineageQueryUsesTheLabelIndex` plans a seq scan and fails. **It does NOT reset between runs, and the whole suite shares it** (`dropDaemonRows`' doc comment, `test/integration/db_child_state_test.go`), so a DB-backed test must be idempotent across runs: never assert on a global row count, and never search for a fixed literal term you insert — every earlier run's rows are still there. `seedRecallWindow` (`test/integration/child_recall_test.go`) is the worked example: a per-run unique term plus a `t.Cleanup` that deletes what it inserted.
- **`go test -run` is an UNANCHORED substring match, so a verify command silently skips tests its pattern doesn't prefix.** Check that every required test name actually contains the `-run` pattern before trusting a green run. When a pattern and a set of pinned names conflict, a pattern-prefixed shim whose subtests call the pinned bodies (`t.Run("…", TestPinnedName)`) satisfies both.
- **`pkg/execpool`'s `TestStreamLimitWaitsRatherThanFails` can hang until the whole package times out (10m), on an untouched `main` as much as on a branch** — an in-memory http2-over-`net.Pipe` transport test, so the hang is environmental, not a code failure. Before debugging a `make check` timeout that names only `pkg/execpool`, run that one test on `main` and compare. Treat it as the sole failing package or not at all. A test that SIGKILLs the daemon "mid-turn" must wait for the LLM request to arrive (`blockingFakeLLM.arrived`, `test/integration/restart_resume_test.go`), not for the child's `streaming` status: the status turns before the request leaves, and a kill in that window leaves nothing to re-issue (the child stays `idle`, signature `fake saw 0 request(s) before kill`). `cmd/rafikid`'s `TestHandleClaudeAbort_InterruptsAndResumes` ("child was not resumed under the same childID after abort", ~8s) is load-sensitive the same way: it passes solo and passes the whole `./cmd/rafikid` package with `-race`, and only trips under the full concurrent suite. A streamed turn's `message_update` count is a flush cadence, not a property of the turn, so frame-sequence assertions on streamed turns go through `assertFrameTypesUpdatesCollapsed` (`pkg/fundi/engine_test.go`), which collapses consecutive `message_update` entries only — a duplicated `message_start`/`message_end` or a turn that emitted none still fails.
- **This dev environment wraps `go test` (and other dev commands) through `rtk`, which compacts output to a bare pass count** — SKIP lines are swallowed, so a suite that silently skipped everything looks identical to one that passed. For real test output (verifying a test ran, reading a panic trace, `-json`), invoke the toolchain directly: `/usr/local/go/bin/go test ...`.
- **A non-interactive shell on this machine lacks `/opt/homebrew/bin`, and `fundi.BuildRuntime` hard-requires `rg` on PATH** — so `make check` from a bare shell fails ~40 engine-spawning tests (pkg/fundi, pkg/inproc, pkg/executor, cmd/rafikid, test/integration) with `ripgrep (rg) is required but was not found on PATH` or children that exit at startup (`0 live executor(s)`, prompt-delivery timeouts). Prefix `export PATH=/opt/homebrew/bin:$PATH` — treat that signature as missing-rg, not a code failure. `uv` is likewise absent: the python-SDK integration tests SKIP. `make proto` needs the same prefix plus the freshly built plugin dir: the executor.proto invocation resolves `protoc-gen-go` by NAME on PATH (no `--plugin=`), so export `PATH="$PWD/bin:/opt/homebrew/bin:$PATH"` or it dies with `protoc-gen-go: program not found or is not executable` — the plugins are built into the gitignored `bin/` by the proto target itself.
- **Setting `Accept-Encoding: gzip` by hand on an outbound request DISABLES Go's transparent decompression.** `http.Transport` only gunzips when the request's header is empty; set it yourself and you get raw gzip bytes with no error. A fixture server answering plain JSON can't catch this — a test must actually gzip its body and set `Content-Encoding: gzip`.
- **Deleting a git worktree leaves golangci-lint's cache keyed to the dead path, and the next `make check` in a different worktree reports phantom failures** citing files by their old absolute path plus `failed to parse file` warnings. `golangci-lint cache clean` fixes it. Suspect this whenever `make check` fails on code you didn't touch, especially right after `git worktree remove`. The same tool also refuses to run twice at once: `make check`'s lint step dies with `Error: parallel golangci-lint is running` (exit 2, no package named) whenever another golangci-lint holds the machine-wide lock, so with subagents working in parallel, wait for the lock to clear and re-run rather than reading it as a code failure.
- **The migration chain must be contiguous 1..N, and `Migrate` skips by version NUMBER, not name.** `loadMigrations` hard-fails on a gap or duplicate — check the max version in the TARGET database before adding a migration, not just the highest file on your branch, or two branches can silently claim the same number.
- **Isolating a scratch daemon means isolating a PROFILE under an isolated `XDG_CONFIG_HOME`, not an env var.** `pkg/profile` is the only resolver: `-P` > `$RAFIKI_PROFILE` > the `current-profile` pointer > bootstrap. `RAFIKI_URL`/`RAFIKI_TOKEN`/`RAFIKI_SOCKET`/the three `RAFIKI_DEFAULT_*` vars are hard client-side errors (`profile.CheckRetiredEnv`), because each was a global that couldn't serve two daemons. `rafiki executor serve` is exempt structurally (it never calls `newConnectEndpoint`) — don't add the guard to the root command's `PersistentPreRunE`, that breaks it. Scoping rule for new settings: per-profile is the default; global is only for properties of the person that no daemon influences (`configKey.global` — currently just currency). Two still-true traps when isolating a scratch daemon: it does not migrate on startup (a fresh database logs `relation "conversations.child" does not exist` and carries on degraded), and `make check` reads the working tree, so nothing may edit it concurrently — capture the gate's exit code directly (`make check > log; echo $?`), since `make check | tail` reports tail's exit code instead.
- **No `Co-Authored-By` trailers in commit messages.**
- **`make check` (vet + golangci-lint + unit tests, `-race`) is the only gate — there is no CI on this repo.** Run it before considering anything done.
- **Tests assert with `github.com/multigres/testkit/assert`; `Eq` is `comparable`-generic and refuses `[]byte` and non-comparable types** — use `EqDeep`/`EqDiff` for byte slices and structs, and note `Collecting.Greater` takes `(bound, value)` (asserts value > bound), the reverse of the stdlib reading order.
- **DB-backed tests silently skip without `RAFIKI_TEST_DSN`** — a green `go test ./...` does not mean the store/insights/agentcli code was exercised. Source `.env` first (`set -a; . ./.env; set +a`) and check the skip count, not just the exit code. The inverse signature is environmental too: every DB package failing at once with `database "rafiki_test" does not exist` **at 127.0.0.1:5433** means the run dialled the wrong server (the `pg` container, not the disposable `pg-test` on 5434 that `.env` names) — the process did not have the documented DSN; re-run one DB package directly with the sourced `.env` before debugging code. `pg-test` is tmpfs and disposable, so after a container reset recreate the seed db: `docker exec pg-test psql -U postgres -c 'CREATE DATABASE rafiki_test'`.
- **`agent_spawn`'s `cwd` does not isolate a child — verify the worktree, never assume it.** A child spawned with `cwd=<worktree>` can still end up split-brained: file tools write into the worktree while bash verifies/commits in the main repo, which is misread as the edit tool silently losing writes and can end in a commit directly on `main`. Every dispatch needing isolation carries an explicit block: `cd <worktree> &&` first on every bash call, absolute paths under the worktree for edit/read/write, a `pwd`+`git rev-parse --show-toplevel`+`git branch --show-current` check before the first edit (blocked on mismatch) and again before committing.
